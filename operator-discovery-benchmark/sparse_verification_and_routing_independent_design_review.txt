Sparse exact verification and default routing independent design audit

A primal certificate is a weighted finite sum. An exactly zero shared weight contributes the zero polynomial, so expansion of that group's atoms can be skipped without changing the coefficient identity. Admission still requires strict exact weights, complete shared dimensions/order, source/generator and original target bindings, nonnegative square weights/internal square factors, and validity of every ACTIVE relation premise. Untrusted zero groups need a declared schema policy: either validate premises too or explicitly rely on a hash-bound trusted generator; a zero multiplier must not disguise invalid active premises. No approximate-zero threshold is admissible. All nonzero groups and the complete lhs must be expanded exactly, with all nonconstant residuals zero and only a computed nonnegative constant slack appended.

A dual functional must be nonnegative on EVERY square/PSD generator and vanish on EVERY relation column. Zero primal weights are irrelevant to that requirement. Sparse support of a primal candidate is not a dual-generator filter. Full stacked monomial coverage must remain explicit.

Adversarial tests: bool/float/negative square weights; noncanonical or malformed rational text; missing/extra group dimensions; reordered shared weights; altered original target/horizon; zero weights around expensive groups; tiny exact nonzero weights that must expand; hidden unsupported nonzero relation coefficient; invalid active prime/factor/inverse premise; mismatched shared instance weights; residual crossing/target boundary omission; false constant slack; incomplete dual column domain. Compare sparse and dense exact residuals on anonymous small fixtures, not large actual-score runs. No infeasibility theorem follows from missing resources.

Entrypoints inspected: run_expanded_probe.py invokes require_verified_runtime and uses explicit stage flags/summarize-only; detector_workflow_guard.py guards optimized Python, unused sealed destinations and runtime boundary, with legacy run_worker bound to inverse_prefix_search.py. Cancellation stages currently use separate freeze/run runners and published latest pointers. A NEW versioned dispatcher can default future discovery to optimized sources, while explicit legacy replay remains bound to old frozen manifests. Preserve all old source/artifact hashes, refuse existing run destinations, freeze new code/protocol before scores, and publish new latest pointers only after independent receipts. Optimized means resource-efficient implementation, not Python -O (existing safety guard forbids it).

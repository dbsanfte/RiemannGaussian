Search JSON contains programs, training_scales, final_scales, and solver limits.
Each program must declare a boolean allow_constant_slack, extended dictionary,
and explicit none/zero_cubic constraint. The example retains the established
critical and unsigned calibration programs, train1,2,3,5 and final7,11. These are
already-used development scales, not new statistical holdouts. Output must be an
unused directory. Final evaluation uses frozen training weights without refitting.
The --timeout value is a global wall deadline for EACH dispatch phase; time_limit
in search JSON governs each solver, and --time-limit also governs each audit.

Execution:
- Spawn independent candidate searches and then independent final-scale checks.
  Workers construct cases locally; queues carry small specifications/receipts.
  Full certificates are written by workers instead of copied into parent memory.
- Default four workers, at most eight, clamped by affinity/cgroup CPU budget and
  the explicitly allocated worker-memory budget. Use --workers 8 with a fitting
  memory budget when desired. Numerical library thread environment is one per
  worker to avoid nested oversubscription. HiGHS is explicitly configured with
  threads=1 and parallel=False: environment variables alone did not constrain
  its separate native scheduler. A fresh-process test checks actual Linux thread
  count, and worker receipts record observed threads at completion.
- The CLI defaults to 1GiB address-space limit per worker and 4GiB for worker
  concurrency; these are address-space limits, not observed RSS or a hard cap on
  the entire Python parent+OS process tree. The parent has separate bounded
  payload/receipt/inflight limits. Oversized/failed/timed-out jobs remain missing;
  no implicit serial retry or disappearing candidate.
- All source files, protocol and input are snapshotted before work. Exact candidate
  weights and their receipt hashes are sealed before final evaluation. Runtime
  versions, source/template hashes, per-job CPU/wall time and peak RSS are saved.
  Failed/missing resource states and numerical infeasibility stay distinct from
  mathematical refutations. Python -O is rejected.

Arithmetic work saved:
- grouped_arithmetic_sparse.py validates EVERY source polynomial, horizon, fixed
  weight and arithmetic premise, but expands only nonzero weighted primal terms.
  It checks the entire original target and exact constant remainder.
- check_grouped_arithmetic_sparse.py independently checks these identities and
  exact expanded certificate bindings, without importing producer mathematics.
  Zero-weight input validation and premise checks remain mandatory. All generator
  columns are still required for a dual-cone certificate; no sparse dual shortcut.
- cancellation_sparse_synthesis.py uses a CSC numerical proposal matrix and
  FLINT exact rational support reconstruction. Float results never certify a bound.
  Native elimination has pre/post deadline checks; the containing process-pool
  deadline can terminate a stuck worker. Internal native work/bit limits are not
  claimed as hard caps.
- A bounded per-worker exact structural-column cache avoids repeated preparation
  when only the target lhs changes. Full structures and limits form its key;
  every lhs is revalidated, and returned columns cannot mutate cached copies.
- Construction uses the previously calibrated checker-side factor builder once.
  The algebraic certificate audit is independent of synthesis, but construction
  is shared in this optimized route; this is not two independent case rebuilds.

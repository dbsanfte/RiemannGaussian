The implementation validates complete instance shape/horizon, canonical rational source coefficients, all fixed/nonnegative square weights, all polynomial index/degree bounds, and every primitive relation including inactive groups. Relation validation is cached only within a fixed target/horizon. It expands only nonzero-weight terms, checks the full original polynomial residual, and permits only an explicitly enabled nonnegative constant remainder. The appended scalar square has exactly that coefficient. Thus the returned certificate is identical to the old producer whenever both admit the same mathematical input and complete successfully. Exactlyzero groups are skipped algebraically, not silently removed from the declared source. Source sealing and instance hash binding remain the caller's workflow obligation.

The producer uses the ordinary arithmetic relation whitelist; the independently implemented checker separately establishes each premise and complete polynomial equality. No signed sequence evaluation or new bound is used. There is no dual-cone optimization here: dual separation requires every generator. The source changes only instantiation resource behavior, not the proof cone.

Five focused tests compare full canonical certificates with old grouped_arithmetic_synthesis on mu and c, rational weights and both slack modes; verify with the independent arithmetic checker; and reject inactive false factors/out-of-horizon/noncanonical inputs, negative square weights, false full targets, negative slacks, and degree/bit/horizon/column/work/time violations. Empty groups with a rational constant slack also agree. No old frozen producer was edited.

Resource semantics: bounds apply to source validation and performed products/merges; inactive product sizes are intentionally not materialized. Work count includes premise-budget charges and explicit multiplication/merge/parse proxies; it is not a hardware-cycle count. Time limits are boundary checks, not preemptive interruption of every primitive or JSON operation. max_denominator is only checked for a positive parameter value during instantiation, just as in old GS; numerical reconstruction enforces its own denominator cap, while instantiation bounds actual coefficient bits. Do not advertise max_denominator as an enforced denominator bound on this API.

The real accepted unsigned calibration benchmark uses unchanged coefficients at X7 and X11 and compares COMPLETE certificate digests to the archived X7 certificate and the independently constructed X11 expansion. The latter preserves its original frozen missing_resource record. Benchmark results are verification evidence only, with no refit or all-scale critical claim.

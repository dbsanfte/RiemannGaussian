# Zero-free theorem explorer

The interactive view follows the actual declaration dependencies of the
current zero-free endpoints. Its coloured zones describe mathematical
families; they do not assert new implications. The README contains only a
linked preview in its zero-free section.

## Sources of evergreen metadata

| Information | Authoritative source |
| --- | --- |
| Current endpoints, exact scope, toolkit notes | [proof-status.json](proof-status.json), generated by [GenerateProjectStatus.lean](../scripts/GenerateProjectStatus.lean) |
| Dependency edges, full statements, docstrings, declaration ranges, transitive axioms | Compiled Lean environment, exported by [ExportTheoremGraph.lean](../scripts/ExportTheoremGraph.lean) |
| Family labels, colours, module assignment, optional theorem reading labels | [theorem-explorer/metadata.json](theorem-explorer/metadata.json) |
| Per-declaration axiom results and full uncollapsed references | [Raw Lean export](theorem-explorer/lean-graph.json.gz) |
| Endpoint axiom audit, source hashes, metadata provenance | [Graph audit](theorem-explorer/audit.json) |

The existing toolkit records are linked from relevant theorem inspectors.
Their explanatory text never supplies dependency edges. New declarations
are included automatically when a current endpoint depends on them.
Theorem descriptions normally come from Lean docstrings. An optional exact
name entry in `metadata.json` can add a short label, summary, family override,
documentation link, or `overview: true` reading signpost. The builder rejects
stale theorem names and unclassified modules. Specific module assignments
take precedence over the longest matching module prefix.

## What an edge means

Solid arrows are direct constant references in elaborated declarations.
Dashed arrows are witnessed paths through collapsed declarations. Select an
arrow to inspect each intermediate declaration and expand the path. Statement
references are distinguished from proof-body references. A reference is not
a claim of minimal necessity, equivalence, or an implication without the
target's other hypotheses.

The full project dependency closure is exported, including definitions,
private lemmas and generated helpers. External Lean and mathlib references
are boundary leaves; their complete transitive axioms are still collected.
Every node must depend only on `propext`, `Classical.choice`, and `Quot.sound`.
Generated helpers link to their enclosing Lean declaration with that fact
explicitly labelled. Source locations come from Lean's declaration ranges,
including original private definitions for inlined pattern-match equations.

## Regenerate and check

Use the pinned Lean toolchain and Node 18 or newer. From the repository root:

```sh
lake build --wfail
lake env lean -DwarningAsError=true scripts/GenerateProjectStatus.lean
lake env lean -DwarningAsError=true scripts/ExportTheoremGraph.lean
python3 scripts/build_theorem_explorer.py
python3 scripts/build_theorem_explorer.py --check
node scripts/check_theorem_graph.cjs
python3 scripts/test_theorem_explorer.py
```

The exporter writes its intermediate file under `.lake/theorem-explorer`.
The builder produces deterministic site data, source/document snapshots,
the compressed raw export, the audit and the small README preview. Source
declaration lines, hashes, linked documentation, endpoint names and permitted
axioms are checked. CI regenerates and compares these artifacts after the
strict Lean build and project lint. Ordinary repository soundness gates
remain in force for theorem changes.

Open [the local explorer](theorem-explorer/index.html) directly in a browser,
or serve it with `python3 -m http.server 8000` from the repository root and
visit `http://localhost:8000/docs/theorem-explorer/`. There are no runtime CDN
dependencies. Browser data is loaded by local scripts, so file previews work.
Before publication, source buttons open the exact local source snapshot;
published source buttons link to the verified Git commit and line on GitHub.
The local source and Markdown mirrors remain available in either version.

## Browser and devcontainer

The repository now has a [.devcontainer/Dockerfile](../.devcontainer/Dockerfile)
with the pinned Lean toolchain, Node and a native Chromium browser installed
through Playwright. The matching Python package version is pinned in
[requirements-browser.txt](../scripts/requirements-browser.txt).
Outside the container, install the test browser with:

```sh
python3 -m venv .lake/browser-venv
.lake/browser-venv/bin/pip install -r scripts/requirements-browser.txt
.lake/browser-venv/bin/python -m playwright install --with-deps chromium
.lake/browser-venv/bin/python scripts/test_theorem_explorer.py
```

## Publication

GitHub does not run scripts or allow an interactive iframe inside a README.
The linked SVG opens the GitHub Pages site. The Pages artifact is assembled
only from a clean committed checkout after the Lean, metadata and browser
checks. Its release record contains the exact source SHA and Actions run.
Enable GitHub Pages with **GitHub Actions** as its source before the first
deployment. Publish the Lean sources together with their generated explorer,
so every source link resolves to the same checked commit.

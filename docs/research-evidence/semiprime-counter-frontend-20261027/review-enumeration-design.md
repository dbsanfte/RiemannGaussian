# Independent enumeration/design review

Disposition: PASS for the finite semantics and computable data paths with the explicit cost qualifications below. The generic mathematical counter wrapper is not itself an executable counter. No source edits, build duplication or tests were performed. Final source hashes are captured after author freeze in review-enumeration-source-hashes.json.

## Explicit enumerations and preprocessing

FiniteEnumerations constructs Fin lists, disjoint sums, Cartesian products, dependent incidence lists and finite function lists by literal recursion. Transport uses a supplied equivalence; the concrete macro equivalences are constructor case maps, not choices of representatives. Lists are noduplicate and complete by proof. MacroFiniteEnumerations enumerates actual ordered signal/vertex/port constructors, including the two edge endpoints and equality vertices of the subdivided graph. It does not enumerate all Boolean edge assignments or local truth tables.

There ARE materialized source word and universal-type lists: their sizes are r^Q and r^(2Q), respectively. They must not be described as list-free or polynomial uniformly in arbitrary r,Q. They are polynomial in the public network size only after the actual scheduled D-budget theorem is instantiated. Score terms include all incidence pairs and Q variable pairs, including repeated original incidences, of size M²+Q n². Construction/storage and each function-word equality/lookup have polynomial overhead in these list sizes and Q. The counted word theorem bounds actual local-term evaluations; it does not include every allocation, lookup, rational bit operation or source-list construction. These are polynomial preprocessing under the schedule and the established height bounds, rather than zero cost.

MixedRadix.decode recursively uses finite div/mod products. It constructs no full summary list and works even with zero radices as an equivalence between empty domains. Runtime summary radii are positive. Access to decoded components may repeat polynomial decoding; cache the current tuple or charge all accesses. Its filtered equivalence preserves explicit list order and uses finite inverse lookup, not classical choice. Repeated filtering and idxOf are polynomial-time costs, not unit reads.

## Mathematical wrapper versus executed design

EnumeratedCounter is inside a noncomputable section and uses the mathematical selected nodeCertificate, finite sums and semantic search. Its prefix/search theorems remove a desired count-correctness premise but do NOT make that wrapper an execution algorithm. The file already states this runtime scope. Supplying concrete source enumerations alone does not computationalize every downstream mathematical finite inverse or representative. The new executed path is separate and must be joined by its semantic theorems.

IndexedNodeCertificate.Data stores literal Fin group sizes, selected integer rows and a concrete partition. Its certificate uses actual false-first representative search; span coefficients and representative-validity proofs are erased. Its noncomputable section is appropriate for term/groupValue and the mathematical fibre expression, not a license to compile arbitrary data functions without implementations. Actual fibreAt acquires representatives once, and the theorem identifies that result with the certificate extensionally.

ExecutedNodeDesign.columns is the actual filtered-coordinate equivalence. selection is executed rational elimination retaining original integer row IDs. C consequently keeps the original bound W, not a normalized rational row bound. selected_count identifies its count with the actual original rational row rank. The span proof transfers integer-kernel annihilation from full constraints to selected constraints, then recovers rational row span; factor ownership hfactor supplies exactly the off-group locality premise. This is the required native span, not assumed global count correctness.

The data constructor's m, C and grouping are function fields, not automatically materialized tables. Repeated m/C evaluation can repeat selectedIndices/selection or filtering. An implementation claiming preprocessing once must cache the per-node column lists, selected row IDs and integer matrix. Without that cache, the present repeated computations have polynomial overhead in the explicitly bounded row/column dimensions, so no new exponential factor is exposed. Source L.head/L.constraints also require cached/charged source implementations; a semantic Layout.Data value is not by itself a primitive-cost supplier.

IndexedFibrePacket.packet_eq_sum is a proof-only definitional identification with the existing native packet. Its Fintype sum does not implement a list-free summary traversal; PacketArrayExecution supplies that separate traversal. It assumes neither an acquired whole packet value nor a global count oracle.

## Runtime handoff

For a concrete executed counter, use the macro enumerations, actual source builder, cached executed row selection, indexed certificate, mixed-radix code traversal, native-group callback, and array packet traversal. The remaining equality joins are mathematical proofs; their erased classical reasoning causes no runtime branching. All physical index/set/division costs still require polynomial finite-encoding overhead and all rational operations require the independent bit-height/backend attachment. No primitive-machine bound follows solely from these seven files, and no hidden full-exponential list was found beyond the explicitly paid source alphabets.

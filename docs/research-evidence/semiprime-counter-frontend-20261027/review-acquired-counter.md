## Repaired executable-interface defect (final re-review)

The old executable count/fibre/node signatures took a Data certificate indexed by `rows : ... -> Polynomial Q`. Although polynomial rows were intended only as specification metadata, this is a non-Prop term index: the actual `#eval` call retained a noncomputable rows dependency. Thus the prior algebra/data-flow PASS did not establish that a plain runtime caller could compile. The preserved failing AcquiredCounterSmoke log exposed a real interface defect; it was not merely a slower elaboration or an arithmetic exception.

The new RuntimeDesign has ONLY runtime fields: r,h,m,W, grouping, assigned and original integer C. Runtime fibre/node take explicit rational sample t and this pure record; runtime count takes `Fin Q -> RuntimeDesign n F`. Independent `#check @fibre/@node/@count` confirms their only implicit metadata are n,F,arity. There is no polynomial rows argument or certified Data index in any of these executable signatures.

`runtimeDesign` is the one-way semantic view of certified Data. fibre_spec/node_spec/count_correct use it to prove that the pure execution returns the native polynomial/Taylor/contraction values. Certified Data, its polynomial row index and span proofs are confined to this semantic bridge and correctness theorems; they are not inputs required by a pure runtime count invocation. An original-input runtime design supplier still has to be constructed/paid, as already stated in the frontier. This repair does not assume a global count certificate or change the algebraic algorithm.

Independent targeted replay of RuntimeDesignSmoke compiled with autoImplicit=false/warningAsError=true. Its actual count results are `(1,2428)`, `2`, `0` (respectively truth predicate value/work, constant-one count, constant-zero count). The signature and replay logs are `review-runtime-signatures.log` and `review-runtime-smoke.log`; these diagnostics establish executable interface closure on the fixtures, while the existing all-input theorems establish semantic correctness. They are not a factoring-success/runtime campaign.

## AcquiredHermite

`node` binds `acquired := acquire t` once, builds a literal J-element coefficient copy, then executes hermiteNode. The callback's own Run.work is retained, rather than merely charging the eventual Hermite arithmetic. Reading and copying the finite packet is separately charged. `packet_correct` uses only Spec below J; values above J are neither assumed nor required, and a shorter actual input array is padded through the existing coefficient/getD convention.

The intrinsic hermiteNode builds its cardinal jet and scalar cardinal factor, executes cached quotient/inverse/multiplication and finite evaluation, and its nodeWork bound includes those actual operations. AcquiredHermite does not replace these with a supplied Hermite coefficient or inverse. `reconstruct` streams indices 0..Q-1 with a scalar accumulator; each callback occurs once per loop step, with its result and work cached. The equality to the older hermite functional is proof-only: its function-valued RHS is not the runtime algorithm and does not license re-execution for free.

`reconstruct_correct` retains hJ>0 and the strict polynomial degree bound <Q*J. A hypothetical Q=0 cannot satisfy that degree bound; no silent interpolation exception exists. `reconstruct_work` includes the SUM of actual callback works, packet copies, node reconstruction work and all scalar accumulation steps. It is a rational-arithmetic/read/control ledger, not a primitive bit-time theorem. The callback may be arbitrarily expensive unless its separate work/resource specification is instantiated.

## NodeArrayExecution

The revised runtime source is explicitly supplied row coefficient ARRAYS, pure RuntimeDesign integer measurements/partition/ownership fields, and paid integer local-entry reports. The polynomial-indexed certified Data appears only in semantic theorems via runtimeDesign. `nativeLocal` computes corrected Taylor inputs from those row arrays and caches them before the depth-first multilinear recursion. `nativeGroup` materializes original-coordinate base bits once, traverses the literal factor indices, uses unit jets for unassigned factors, and performs actual local calls/products. `fibre` scans the FULL mixed-radix summary box and actual local Boolean fibres, computes representative searches and measurement/forced gates, and acquires native group products. There is no runtime full-fibre, Taylor-packet, H-value or final-count oracle.

The semantic bridge fibre_spec uses the executed representative/native certificate equivalence and the native group theorem. It does not require representatives of different groups to be the same original Boolean assignment. Unattained labels have empty local fibres and contribute zero even though their default representatives are defined. `node` runs the literal ternary support traversal with signed fibres, cutoff J-1 and the noduplicated exhaustive Fin n variable list. Thus node_spec returns the actual global Taylor coefficients at t.

The new `count` uses AcquiredHermite.reconstruct with this actual node callback at sample t=a+1. `count_correct` assumes only actual row degree, coefficient-array agreement through R, original-coordinate restoration and M*R<Q*J, plus native Data certificates. It concludes the original contraction. It does not assume desired Taylor/fibre/count values. Arbitrary integer entry reports are algebraically allowed; Boolean-height and nonnegative counting consequences require the separate actual 0/1 entry instantiation.

`node_work` retains all four exponential traversals: inclusive signed support menu, full summary-box cardinal, local fibre 2^H scan, and the local 2^W multilinear leaves inside groupBudget. Representative search is charged per summary. `count_work` sums the per-node acquisition budgets before adding reconstruction. It does not suppress any one of these loops.

## Caching and retention

The code streams rather than materializes all Boolean assignments, summary codes or support pairs. Recursive local evaluation can hold a completed sibling jet while computing the next branch; polynomial depth times finite-J arrays suffice, not a stored 2^W truth table. The support recursion holds a constant number of branch arrays per frame, again depth O(n). Product loops retain finitely many current group/factor results. AcquiredHermite returns a scalar and discards previous node packets once accumulated. These observations are constructive polynomial-space reasoning, not a proved allocator/garbage-collector/TM theorem. Array/Fin/grouping accesses and persistent-function lookup costs require the separate flat-binary/control interpretation.

## Two important scope qualifications

1. `design a`, source arrays and local-entry T are INPUT descriptors/callbacks to NodeArray. Its work bound pays actual native node-array acquisition and reported entry work, but it does not charge generating arbitrary `design a` or source coefficient arrays, or arbitrary callback internals not reflected in their reports. ExecutedNodeDesign, computed row selection and source construction must supply those separately. The wording “all source-node acquisitions” should mean the displayed native node callback, not a whole public layout compiler for free.
2. The new localEvaluate is a recursive suffix/branch tensor evaluator. Its intermediate lo/hi values are not literally just the full original-T truth-mask expressions in built_truth_prefix_representation. Their heights follow by applying generic evaluate_representation to the fixed-prefix restricted integer table and suffix ports (same abs<=1 entry bound), then padding denominator powers to the parent arity if desired. Multiplication by z0 or 1-z0 and the two-child sum use the existing common-denominator convolution/sum bounds. This supplies the mathematical polynomial-height argument; a full tracked interpreter-to-prefix-height attachment is still a separate formal interface. No mathematical contradiction or new exponential cost was found.

No substantive algebra correction requested. The remaining distinction is exact executed expression/operation semantics versus completed machine cost/space and source-acquisition refinements.

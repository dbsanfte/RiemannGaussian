Principal findings
------------------
1. The SGLang BF16-origin vocabulary alphabet assumption DOES NOT TRANSFER.
   LLAMINAR persistent logits are FP32 outputs from FP32 accumulation. Native
   BF16 weights are expanded/multiplied into FP32 sums, not a BF16 output that
   is subsequently widened. Quantized weights also produce FP32 logits.
   Actual post-transform argument duplication must be measured; source proves
   no small-alphabet bound. Casting those logits to BF16 changes the contract.
2. Production ordinary stochastic sampling and stochastic MTP target sampling
   already select top K raw adjusted logits first, then evaluate only K<=256
   exponentials. V=248320 does NOT imply V exp calls for ordinary sampling.
   Greedy ordinary sampling and actual production MTP draft sampling have zero
   vocabulary-softmax exp calls. Actual MTP drafts are greedy, q is one-hot.
3. Routed MoE is different: production CUDA/ROCm computes all E=512 exp calls,
   full FP32 softmax, then selected K=10 renormalization. The SGLang baseline
   'only 10 exp already' is false here. Raw-top10-only softmax is real-algebra
   equivalent when weights normalize, but is not bitwise equivalent to this
   two-stage floating computation and can change rounded top-k ties.
4. Strongest strictly bit-preserving small hook: SamplingMath sorted-K helper
   can reuse the evaluator for adjacent equal ACTUAL shifted FP32 argument
   bits while retaining every ordered add and the same normalization stages.
   Cost is a previous-argument comparison/cache rather than global grouping;
   upside is bounded by K, duplicates unknown, may not pay. Larger MoE 512->10
   savings need a new arithmetic contract or a certificate of the existing
   rounded result, not just real cancellation.

Canonical top-k/top-p exact arithmetic
-------------------------------------
kernels/common/SamplingMath.h:2270-2330:
  temp = temperature>0 ? temperature : 1
  max = sorted_logits[0]
  for i=0..K-1, valid token: w[i]=expf((logit[i]-max)/temp); total += w[i]
  nucleus prefix chosen by repeated cumulative += w[i]/total; stop >= top_p
  (only when 0<top_p<1 and total>0)
  recompute nucleus_total = sequential sum w[0..nucleus-1]
  write valid prefix probabilities w[i]/nucleus_total, inactive ids=-1, probs=0.
Thus K valid entries -> K exp calls, K sequential accumulation steps, up to
K divisions/adds for cutoff, nucleus-length accumulation, nucleus divisions.
The helper does NOT multiply each weight by one common reciprocal in source.
Changing cutoff to cumulative_raw >= top_p*total changes operation order.
Changing first normalization to an algebraic fused formula changes rounding.
Changing sum order, K-wide parallelization, or dropping tiny weights can change
cutoff, stored probabilities, MTP acceptance, and seeded output.
The direct sampler helper at :2332-2392 similarly computes K weights and
cutoff but thresholds against raw nucleus_total; it is not automatically bit
identical to build-compact-table then re-sum stored probabilities.
Sampling compact distributions at :2228-2268 re-sums positive stored probs,
uses clamp(threshold)*total and an ordered positive-probability scan with <=.
Skipping this re-sum because probabilities 'sum to one' changes semantics.

Routed MoE actual semantics / obstacles
---------------------------------------
CUDA kernels/cuda/moe/CUDAMoEKernels.cu:
  prefill/grouped softmax_topk_kernel :14145; :14230-14247 raw-logit selection;
  :14250-14291 all E exponentials, fixed256-thread strided local sums, binary
  block sum tree, divide every exponential by full denominator, overwrite
  logits with full probabilities; :14294-14313 sequential selected sum then
  selected probability / selected sum when normalize_weights.
  decode runtime :14344 and unique-owner runtime :14520 compute full softmax
  FIRST then top-k over rounded probabilities (:14404-14426 and14558-14586).
  Thus raw-logit top-k and rounded-probability top-k can differ on near ties;
  lower expert id tie rule applies at the actual comparison values.
ROCm kernels/rocm/moe/ROCmMoEKernels.hip:
  wave64 decode :14867, full E exp at14940; wave/shared FP32 sum, inv_sum=1/Z,
  E multiplies into full probability rows, select rounded probabilities, then
  sequential selected sum -> inv_topk_sum=1/S -> K selected multiplies.
  grouped decode-equivalent rows :15144-15310 mirrors that wave arithmetic.
  unique-owner :15015 also full E exp. Other decode and K-part paths remain
  full softmax too (:14698,:15329).
CUDA does per-value divisions whereas ROCm performs reciprocal/multiplications;
backend math references must therefore be named separately. For E=512,K=10,
full-all-experts softmax uses 512 exp per row rather than 10 on both backends.
The final normalized selected weights mathematically cancel the full Z, but
round(exp_i/Z), round(sum selected rounded probabilities), and final
round(divide or reciprocal-multiply) retain its influence. Full logits output
is also overwritten with probabilities: consumer/snapshot observability must
be checked before eliminating that side effect.

RNG and bitwise contract
------------------------
SamplingMath.h:2126-2178 splitmix64/uniform01 takes top24 random bits, scales
by2^-24. Draw is keyed by logical position and purpose, eight purposes per
position. Clamp max threshold=0.99999994. No stateful CUDA/ROCm RNG substitute
is semantics-preserving. Serial-equivalent MTP can differ if a single compact
probability bit moves a threshold across a prefix. Rejection acceptance uses
stored p/q and exact <= or < branch of the named helper; don't interchange.
:2188-2194 inverse exponential uses clamped uniform, -logf, floor1e-20, inverse.
:2625-2680 one-hot recovered draw derives seed^domain then position*V+token,
maximizes residual_probability*inverse_noise with lower-token tie break.
Penalties use shared explicit RN multiply/divide/subtract (:35-52), so grouping
must use post-penalty/post-temperature actual exp arguments, not original
weights/logits. Equal tokens can split under history penalties.

Build/precision concern: src/v2/CMakeLists.txt:284-289 globally adds CUDA
--use_fast_math --ftz=true --prec-div=false --prec-sqrt=false. No per-source
sampling override found in CMake scans. Thus expf/division source is not a
correctly-rounded libm exp/division spec; need pinned compiler flags, ISA,
FTZ, and generated instruction evidence. ROCm evaluator/reduction is a
separate reference. A correctly rounded REAL softmax certificate does not
establish agreement with these current FP32 approximate pipelines.

Recommended implementation experiments, ordered by contract
----------------------------------------------------------
A. Current-output-bit contract: instrument post-transform shifted argument
   cardinality only in actual K-sized selected tables and E-sized MoE rows.
   Collect all-equal/near-tie/extreme/penalty cases plus real model traces.
   Adjacent run memoization inside shared SamplingMath helper preserves serial
   summation, per-term top-p divisions, nucleus sum, probability divisions;
   only identical actual argument bit patterns share exp. Can similarly reuse
   normalization result by identical numerator bits and same denominator.
   Even ordinary FP32 collisions can occur after subtraction/scaling, but
   no source-backed substantial repetition rate exists. No global V histogram
   or 65536 BF16 lookup should be designed on the SGLang synthetic evidence.
B. Router arithmetic redesign: raw-top10 then selected softmax is the largest
   concrete fewer-exp opportunity (512->10 per routed row), but requires an
   explicit new mathematical contract and complete serial/grouped/backend
   validation, or a rigorous certificate that outputs and route ids match
   the existing rounded implementation. It is not a drop-in bitwise rewrite.
   Check full-probability-row consumers before removing their production writes.
C. Certified low precision: target FP32 stored compact probabilities, prefix
   cutoff and seeded decisions, or router selected FP32 weights/ids. BF16
   output rounding cells are irrelevant here. Enclosures of exact REAL
   softmax alone miss existing approximate exp/reduction/normalization error.
   FP32 output cells are much narrower than BF16: refinement may dominate.
   For no more than256 or512 exps per row, certificate/lookup overhead is a
   substantial obstacle; benchmark end-to-end, no claimed speedup.
D. Full-temperature primitive redesign, only if later selected by production:
   store each first-pass exp once and reuse in original reduction/output
   schedule to remove the repeated V evals without depending on duplicates.
   Needs persistent graph-owned scratch, no hot allocation; ~993280 bytes
   extra FP32 storage per V=248320 row. Saving SFU work can lose to memory
   bandwidth. Do not present this as an optimization of today's production
   greedy MTP draft lane.

Follow-up: production anchors / tests / cheap hooks
--------------------------------------------------
There are NO repeated same-position exp evaluations inside live compact
SamplingMath nucleus loops: scratch_weights[K] already retains each exp and
reuses it for cutoff, nucleus sum and final probabilities. MoE also stores
values[E] and reuses them. Adjacent-argument reuse therefore means duplicates
across different selected tokens, not removing an accidental repeated call.
The row is already sorted for sampling, so no new full-vocabulary sorting is
needed for the adjacent-run hook. Exact reuse still executes every ordered
addition and cutoff division. Low duplicate rate can make comparisons costlier
than the saved exp; cardinality collection is the justified first experiment.

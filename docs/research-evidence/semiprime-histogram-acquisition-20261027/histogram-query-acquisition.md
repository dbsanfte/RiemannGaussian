# Acquiring the original source score without its quadratic descriptor list

The constructive target is an exact source score from the original ports and
selected prefix. The preceding checkpoint still acquired
`T = M^2 + Q*n^2` original score descriptors, even after eliminating each local
completion tree. This effort replaces that actual constructor and descriptor
sweep with deterministic sparse histograms. Old descriptors and count evaluators
occur only in proof specifications. It does not assert the finished primitive
bit/TM exponent or a near-linear whole-family initialization bound.

## The cancellation that removes the incidence pair list

Let `L=r^Q`. Owner keys and factor keys are different namespaces in the actual
original compiler. The complete-word two-port equality kernel, multiplied by L,
is exactly

    P = J + (L-1) D_free + L C_fixed - F_fixed.

Here J is the constant-one kernel; D_free tests equality of two free variable
keys, C_fixed tests equality of two fixed selected words, and F_fixed is the
constant-one kernel restricted to fixed keys. The four corresponding physical
features are constant/all, variable-key/free, selected-ID/fixed, constant/fixed.
Their coefficients are `c = (1,L-1,L,-1)`. This retains the negative correction,
all repeated original ports, all ordered pair diagonals and all prefix phases.

For each of sixteen feature pairs `(f,g)`, stream the actual eligible original
ports into a dictionary using the framed pair of owner/factor feature keys. If
`h_fg(z)` is that key's frequency, put `S_fg = sum_z h_fg(z)^2`. The exact original
incidence count is

    I = L^2 * sum_(f,g) c_f*c_g*S_fg.

`SourceIncidenceHistogram.original_incidence_pairs` proves the kernel expansion
against the original count normalization. `SourceHistogramAcquiredSums` joins it
to the actual old compiler/count evaluator. `SourceHistogramDictRefinement`
discharges the dictionary's equality interface using the actual acquired compact
candidate bank and actual selected-prefix trie. `SourceHistogramFeatureBits`
produces the physical eligible keys and joins their actual squared counts to
these original histograms. No projection, supplied frequency, count answer,
quadratic raw moment array or matrix/resolvent is a runtime input.

## The cancellation that removes the head pair list

Let p and f be the actual fixed/free vertex counts. Stream each fixed vertex's
Q physical colours, paired with its coordinate tag, into ONE histogram; let C
be the resulting sum of squared bin frequencies. Coordinate tags prevent
unintended cancellation or collision between different coordinates. Then

    H = L^4 * (C+Q*f) + r^(4*Q-1)*Q*(2*p*f+f*(f-1)).

`SourceHistogramHeadAggregate.original_head_lane` proves this equality for the
actual original head evaluator and arbitrary original environments/Nodup
remaining lists. `SourceHistogramHeadOriginal` proves that the physically
executed histogram and binary counters equal the required C,p,f. A fixed vertex
performs one actual selected-ID lookup and one actual physical row read, parsing
all Q colours once. A free vertex performs the actual counter increment.
`Q=0`, `r=1`, empty partitions, f=0 and parallel ports are included.

## Physical acquisition and exact scalar score

A trie update reads and increments one existing binary counter. If its old value
is k, the square sum changes by `2*k+1`. This updates the physical square-sum
word without a second traversal over all buckets or an enumeration of bucket
pairs. Actual tuple framing is injective, including empty keys and keys that are
prefixes of others. Actual IDs and counters are compact binary words; neither a
padded ID catalogue nor a unary count is substituted by a logarithmic bound.

`SourceHistogramSetup.acquire` acquires original sparse metadata, graph keys,
compact candidate IDs/physical rows, a row dictionary, coordinate tags, scale
words and counters once. `SourceHistogramQuery.score` acquires the selected-prefix
dictionary once, executes the sixteen incidence histograms and single head
histogram, and combines their actual signed denominator-one words. It performs
no rational GCD reduction or native integer-to-word encoding of a count result.

`SourceHistogramQueryCorrectness.incidence_original` and `.head_original` prove
equality with the original count lanes. `.score_original` proves that the actual
executed query equals

    n^2*lambda^2*(r^Q)^4*I + 4*M^2*H.

This is the existing original cancellation objective, with
`(r^(2*Q))^2=(r^Q)^4`; it preserves original scalar-score order after the already
proved positive common-factor/common-offset cancellation. Zero count/weight
cases require no cancellation by n or M and retain every tie. Source words and
the old quadratic descriptor/count list are confined to mathematical proofs.

## Exact source selector and uniform resources

`SourceHistogramSearch.run` acquires the original cache once and uses its compact
candidate bank in the existing physical comparison/copy controller. It supplies
the concrete histogram query itself; no callback or scalar value is provided as
input. `run_refines`, `indexed_refines` and `indexed_original` prove the exact
original output labels and every original left-on-tie decision, for the whole
original family and every shared proof-side offset.

`SourceHistogramQueryBounds` derives all actual input/output widths and the
complete displayed score report from original acquired metadata and selected
menu membership. `SourceHistogramSetupBounds` retains every original setup
producer. `SourceHistogramSearchBudget.run_work` joins these to every reachable
candidate query, comparison and prefix copy. `SourceHistogramResources` proves
`run_report_actual` and `envelope_monomial`: one fixed C,k before all inputs bounds
the actual new selector report in seven original dimensions
`n,F,r,Q,lambda,M=sum arity,L=r^Q`. Neither T nor a separate universal-cardinality
cap is needed. Actual materialized L remains counted, rather than replaced by
its binary length or an unproved small initializer.

## What costs have to remain separate

A length-M acquired key stream of key width B has actual square-sum report
`O(M*(B+log(M+1)+1))`, with logarithmic physical counter widths derived from the
actual stream. Sixteen is constant. The head stream has at most n*Q acquired
keys; one physical row lookup per fixed vertex includes all Q colour parsing and
tagging work. A constant number of denominator-one binary arithmetic operations
uses polynomially many bits in the original logarithmic operand widths.

This per-query gain does not certify a near-linear whole-family acquisition or
full primitive-machine exponent. Actual original graph-key/r/lambda encoders
still have conservative native-input polynomial setup bounds; the candidate
bank and row dictionary are explicitly materialized and paid. Native metadata (including the selector callback's `tokens.length` argument
evaluation), comparison/control/report, immutable references and allocation/tape simulation
remain separate obligations. Selected incidence-label reads for packing, the universal coefficient cache,
pullback and public counter composition must still be joined to a new original
input caller. No old public runtime clock is inferred from value equality.

# Next packing interface investigation — PROPOSAL, not a proved adapter

Read-only investigation, 2026-10-27. All 42 current sources remain unchanged. No build or runtime experiment was performed. Source pins are in the companion JSON.

The concrete next step is an ID-pair packing adapter. Packing needs only equality of universal labels, not their colours. A selected incidence label can therefore be represented by the pair of actual compact word IDs selected at its owner and factor positions. The existing exact search theorem and acquired-bank decode injectivity supply the proof bridge. This is a substantive attainable interface simplification; no canonical theorem or implementation of this adapter currently exists.

## Exact existing seam

`SemiprimeMaterializedSourceWords.labelAt owner factor a indices labels i` pays two `indexRun` searches and two `MaterializedWordSearch.readRun` reverse-prefix reads, then returns `UniversalType r Q 1` with head=owner word and slot(0)=factor word. `labelAt_value` identifies this with `Packing.incidenceType`; `producer_value` identifies the cached original searched labels with `Packing.computedWords`. `MaterializedOriginalSource.label_value` then identifies these labels with `(FiniteEnumerations.searchPacking owner factor en eps).label i`.

The current physical selector is `SourceHistogramSearch.run n F r Q lam arity owner : MaterializedWords.Run (List (List Bool))`. It acquires setup once and executes the existing choice controller; `run_valid`, `run_length`, and `indexed_original` give acquired compact-ID membership, length n+F, and exact original word/tie order when r>0 and lambda>0. Its output is REVERSE chronological: position k is obtained from `fixed.reverse[k]`, not `fixed[k]`.

`SourceHistogramPrefix.acquire fixed` physically builds exactly that position-to-selected-ID dictionary. `lookup_eq` identifies the actual lookup with the trimmed reverse-prefix entry; `SourceHistogramDictRefinement.decoder_reverse`, `stored_mem`, and `stored_decode` identify it with the original total decoder, including the default empty ID. Actual port metadata already carries `PortRecord.ownerCode=v.val`, `factorCode=n+e.val`, and compact physical `ownerKey`/`factorKey`, acquired by `SourceHistogramPortKeys.acquireOriginal` rather than an external label table.

`PaidPackingSnapshot.acquire vertices keys producer` currently expects `producer : I -> SourceUniversal.Run (UniversalType r Q 1)` and `keys : List (UniversalType r Q 1)`. It executes `MaterializedPacking.labels`, every `bucket`, `minimum`, then every `place`, retaining `blocks` plus addresses. Its `acquire_blocks` and `acquire_addresses` identify those with the original packing. `MaterializedPacking.position` is the first incidence position in an ordered bucket; `place` includes precisely positions < blocks. Thus preserving incidence order, not merely frequency, is essential.

`MaterializedSourceAcquisition.acquire R is owner keys producer` calls packing, then `MaterializedSourcePullback.acquire`. The latter acquires `MaterializedSourceRows.acquire (centered r Q R) R keys` ONCE, then all source rows. `SourcePullback.assembled` uses addresses: leftover diagonal identity, zero across different blocks, and `SourceCache.read R keys cache u y` within a block. `SourceCache.read` performs two actual key scans over the universal coefficient cache. Source pullback then sums incidence columns with matching owner.

The existing physical coefficient entry `SourceInterpolationGeneratedBits.acquire A R (a y : UniversalType r Q 1) k` acquires generated syntax/bank and returns an actual coefficient word with correctness/Valid/Width. Its input STILL has native Word-valued universal labels, and its header explicitly excludes original parity/prescription/syntax acquisition from the whole public primitive-clock claim. An ID-pair packing proof does not eliminate this last input seam.

## Concrete runtime skeleton

1. Execute `Search.run` ONCE and retain its report. Acquire `Prefix.acquire result.value` ONCE. Acquire original port records once (or retain the already computed setup rather than silently recomputing it).
2. For every incidence in original factor-major incidence order, perform TWO physical prefix trie lookups using its already acquired owner/factor keys. Copy the resulting compact IDs and frame them with `KeyBits.frame`; `frame_injective` plus `CompactWordBank.decode_injective` proves equality iff original universal labels agree. Keep both component IDs in the cached record as well as the framed comparison key: parsing is unnecessary for later row access.
3. Baseline implementation: produce a complete universal key catalogue from the ACTUAL acquired `bank.ids x bank.ids`, with a fixed paid product order and framed pairs. This has L^2=r^(2Q) entries. Do not enumerate decoded Word functions and do not call the old word-valued producer in runtime.
4. Run physical bucket construction over the cached incidence keys, common minimum, and ordered first-position addresses. A faithful first implementation may use finite scans, fully charged. A trie can avoid repeated equality scans, but must retain original per-bucket incidence order and compute the minimum over the COMPLETE L^2 catalogue, including absent buckets. Omitting zero buckets changes blockCount and is invalid. Observed-key-only optimization needs a separately proved completeness/absence test.
5. Retain addresses `(incidence, Option(block, pairID))`. Establish a proof-only map `decodePair (h,s) = {head := decodeBank h, slot := fun _ => decodeBank s}`. Show decoding the entire snapshot equals old `PaidPackingSnapshot.acquire` for the exact original `searchPacking`. For a new product catalogue order, prove minimum/per-label lookup invariant under complete nodup reordering; do NOT assert equality of its list order with `en.types.values` without proof. Bucket incidence order must be identical regardless of catalogue reordering.
6. Carry pair IDs as universal-cache addresses. Only when computing a universal coefficient for `(pairA,pairY)` fetch their four actual physical colour rows from the acquired bank/row cache. `RowKeys.QueryCache` already retains the actual bank and a physical ID-to-framed-row dictionary, but `readKeys` returns tagged colour keys rather than the raw coefficient-constructor input. Reuse acquired raw rows or add a paid row parser; do not decode semantic Word functions and reencode their answers.

## Exact proof target

For every original incidence i, with labels produced by the actual new search, prove

    decodePair (selectedPair i)
      = (FiniteEnumerations.searchPacking owner factor indexedEn
           (1 / (r * lambda : Nat) : rational)).label i.

Here eps is exactly 1/(r*lambda), matching `SourceScorePhysicalCaller.originalX`; using 1/lambda would change the original source scale. This follows through `Search.indexed_original`, the two prefix lookup refinement lemmas, the actual indexed owner/factor position identities, and `MaterializedSourceWords.labelAt_value`/`producer_value`. It is valid with n or M zero, Q=0 and r=1 provided r>0; lambda>0 is required for search-order transfer. Q=0 has one acquired word ID and one universal pair, not an empty catalogue. Default IDs remain actual bank members; all positions used by actual ports are in range of the completed n+F prefix.

Next prove bucket, position, minimum and address refinement under pair decoding, then assembled/sourceRow coefficient refinement. These are constructive list/map/equality transport obligations; no count, coefficient, terminal score, labels or basis is allowed as runtime advice.

## Costs and remaining boundary

Let B be actual compact ID/key width. Pair lookup/framing per incidence is paid O(B plus actual trie path/payload costs), after the existing prefix acquisition; labels need no Q colour reads. Retaining the full catalogue costs at least its L^2 records and their actual copies, which the original constructor already materializes. A conservative exact scan implementation remains polynomial in M,L^2,B and preserves the existing subpower resource strategy; it is not automatically a near-linear packing implementation. Coefficient-cache construction still has (L^2)^2 universal row/column pairs and R+1 coefficients if materialized literally, with every actual generator/backend/read report charged.

The strongest guaranteed finding is that packing-label equality and exact ordering can be handled entirely with acquired compact ID pairs before any colour access. The missing substantive adapter is original selected-pair acquisition plus decoded snapshot refinement. The next missing physical constructor is original universal coefficient generation from those physical row inputs, followed by cached pullback and the actual public counter join. Source interpolation's native parity/prescription and finite metadata, native list/control/allocation/reference/address costs, and the full primitive public clock remain explicit obligations. No existing whole-report rate transfers merely by value equality.


## Stronger optional sparse packing candidate — NOT PROVED

The complete L² catalogue need not be materialized merely to compute blockCount. Its zero buckets can instead be accounted for by an exact cardinality guard. This improves the baseline proposal above; the warning against *unguarded* observed-key-only minimum remains essential.

Execute a single stream of the ORIGINAL nodup incidence list. For each cached framed pair key, call the actual frequency-trie `bump` once. Retain the physically copied OLD counter as this incidence's within-label rank, alongside its pair key/ID components. Detect old=0 physically and increment an actual compact distinct-bin counter D. After the stream, traverse only trie nodes, collecting counters at occupied terminal payloads; take their minimum with initial cap M. Structural trie nodes with no payload are not bins. An internal terminal node may itself be a bin (empty or prefix-related keys are valid), so traversal must process both its payload and its children. All observed counters are positive.

Use an actually acquired physical L² word (for example the cached histogram scales square), not a supplied universe-size answer. Compare D to L² physically. If D<L², return blocks=0. If D=L², return the minimum positive observed final counter. A D>L² branch is unreachable on the acquired valid-ID endpoint; define it conservatively, e.g. blocks=0, and prove unreachability. Do not substitute semantic Nat cardinalities for this runtime comparison.

The proof has four concrete parts:

1. Every stored pair consists of actual acquired menu IDs. Compact-bank decoding is injective on these IDs; framed-pair injectivity makes observed keys a subset of the L²-element semantic universal label set. Therefore D≤L². With r>0, L≥1, including Q=0 and r=1.
2. D<L² gives a missing universal label, whose original bucket is empty. Thus the original minimum is zero. D=L² gives coverage by finite subset/cardinality equality, so the original complete-catalogue minimum is exactly the observed final-counter minimum. This does not require catalogue order equality.
3. At each stream position, old counter equals the number of earlier incidences with this label. Since the original incidence enumeration is nodup, this equals `MaterializedPacking.position i (originalBucket label)`, rather than merely a count of preceding list occurrences. With duplicate incidence IDs that equality can fail: the old position function returns the first occurrence, whereas streaming ranks increase. The concrete original finite enumeration supplies the required nodup proof; no generic arbitrary-list theorem should omit it.
4. Emit `some(oldRank,pairID)` precisely when oldRank<blocks; otherwise emit none. After proof-only pair decoding these addresses equal `PaidPackingSnapshot.acquire_addresses`, in exactly original incidence order. With M=0, D=0<L² and blocks=0; the output is empty. With no missing bin, every incidence key has positive final count and the stored ranks run from zero through count−1 as required.

This is a genuine constructive candidate: one actual pair-counter update per incidence, compact new-bin counting, one final occupied-payload traversal/minimum and cardinality comparison, then an address-emission scan. No coefficient, label, count, minimum or universe-coverage answer is advised. The trie has at most 1+M(B+1) nodes for actual key cap B; its frequency and distinct counters are ≤M, so compact widths are logarithmic in M. Retained rank/key records are O(MB) cells plus counter words. A paid explicit traversal can visit all nodes once; immutable list concatenation/copying may instead introduce a fixed polynomial overhead unless a concrete stack/accumulator implementation is chosen and charged. Physical comparisons and minimum copies need actual counter-width budgets. L² itself has O(Q log r) bits once acquired, so this guard does not force L² enumeration. Existing setup might independently materialize all L bank rows; this proposal removes the *pair catalogue* requirement, not that already incurred bank acquisition.

No new theorem, runtime adapter, traversal, or clock proof is claimed here. The highest-priority next implementation is this guarded sparse snapshot, with the acquired-ID pair/refinement invariant and exact original nodup stream. Subsequent universal coefficient-cache construction may still enumerate universal pairs and must be charged separately; sparse packing alone does not establish a sparse universal coefficient family or the whole public primitive-bit bound.

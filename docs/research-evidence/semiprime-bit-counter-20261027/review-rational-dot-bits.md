# Independent semantic review: RationalBits and DotBits

**PASS within the explicit primitive-report model.** Read-only review; hashes in `review-rational-dot-sources.json`.

RationalBits' data path uses actual word arithmetic, denominator scanning, GCD, signed exact quotient/division, and paid copying to the supplied template. Its rational interpretation is a specification, not an invoked arithmetic oracle. GCD reduction derives the canonical numerator/positive denominator; zero physical denominator is explicitly totalized to zero. Raw addition correctly requires valid input denominators, whereas multiplication and inversion agree with total rational interpretation. Inversion at zero becomes canonical zero after reduction, consistent with the total ℚ inverse; it does not assert that zero was a unit in an application.

Fixed-width copies can truncate, but `executeOperation_correct` requires a semantic Fits proof for the actual result and derives that no information is lost. `fits_of_representation` obtains it from the previously proved unreduced common-denominator/numerator bounds, rather than an unrelated output-height oracle. Raw temporaries are bounded by 3W+1, so the cubic reduction envelope includes their larger width. The clock theorem charges raw arithmetic, reduction, copying and fixed overhead; no unit-cost rational arithmetic is substituted.

DotBits makes exactly one recursive suffix call, then executes one actual multiply and one actual add. It does not recursively recompute the suffix for either proof or data path. `dotBits_correct` uses input representations over common d/e to derive every product over d*e and every partial sum over that SAME denominator, with numerator bound length*B*C. All actual result Fits claims follow from these bounds. The empty dot product uses a valid literal zero word, and its width theorem correctly needs positive template length. Physical input Width is separate from semantic validity/height: the cost theorem explicitly requires it, so arbitrary zero padding is not free.

`dotBits_cost` charges at most length*(40000(W+1)^3+4)+4 in the report's Boolean/cell/branch model. It does not acquire its input list, prove a global counter array correspondence, or on its own implement a complete machine-space theorem. The interpretation/normalization results likewise do not prove every application has a common polynomial-bit denominator; PacketHeight and the actual input adapters supply that role. No material semantic issue found.

# Complete physical-word row selector

Two NEW modules only: `SemiprimeRowSelectionBitArithmetic.lean` and `SemiprimeRowSelectionBits.lean`. Earlier Rate/SelectionHeight/Temporaries/selector sources and sealed packets are unchanged.

## Actual runtime, not a scalar answer oracle

`SemiprimeRowSelectionBits.run` takes n, the physical template, concrete nested lists of original rational words, and original bounded row IDs. Its state contains only a Boolean active list, a nested physical-word matrix, and retained original row IDs. It never evaluates a rational value, original C function, old run, selected basis/minor, or supplied state answer on its executable path.

Every read uses actual recursive `readAt` list scans. Every residual coordinate acquires all n physical input/state pairs and executes the existing Boolean DotBits suffix loop, then physical negation/addition. Inactive working rows are proved zero, so including all columns is exact and avoids a missing-active-branch issue. The entire residual row is cached once. The first pivot is chosen by a complete physical numerator-bit nonzero test, including signed/padded zero. Normalization retains one pivot-word read and executes actual Boolean inverse/multiply on each cached residual coordinate. Back update executes physical multiply/negate/add in every active nonpivot coordinate; pivot and inactive rows are explicit retained-normalized/zero cases. The full row/flag lists and selected original ID are cached before the next iteration.

Cache allocation/map/fold allowances are explicit:10n+5 for report/payload/clock row and pair caches,20n+20 for the full outer insertion caches. Every physical arithmetic instruction's own clock is retained. No unit-cost rational instruction is substituted.

## Exact correctness and derived widths

`run_refines` proves legality, physical width, all active flags, every stored decoded coefficient, selected-ID order and physical cache shapes against the ACTUAL frozen `RowSelectionExecution.run C ids`. `run_decoded_eq` states exact equality of the entire interpreted matrix/flags/ID state, rather than merely some row-space equality. `run_selected_eq` exposes exact original-row selection for the design builder.

The only logical input contract `hinput` identifies the ORIGINAL encoded integer rows, their legal denominators and existing physical padding. The original bound `|C[j,v]|<=2^bits` determines `selectorWidth n bits`; there is no input contract supplying intermediate state/minor values or output Fits. The old actual-prefix pivot-minor proof supplies a common nonzero integer determinant. Squaring it gives a positive shared denominator for ALL stored coordinates, including inactive zero slots. The derived shared representation controls every dot-product suffix without expanding a generic arithmetic-circuit height recurrence. Existing temporary bounds derive normalization and back-update Fits. No future-pivot unit assumption is used to manufacture a fit; the actual scan chooses the tested pivot.

## Whole loop ledger

`run_clock` bounds the actual returned report by

    runBudget m n W count
      = n(n+1)+n+2
        + count*(2m+1 + insertBudget n W +3),

where W=selectorWidth n bits and every stage of insertBudget is an explicit fixed polynomial:

* residual row: n physical residual-coordinate budgets plus row-cache allowance;
* pivot scan: n*(2n+3W+6)+1;
* normalization row: one retained pivot read, n actual physical divisions and cache allowance;
* update: n concrete row budgets (including all list reads and three physical back instructions);
* active-flag/selected-ID/cache control allowances.

`residualWord_clock`, `normalizeWords_clock`, `backWords_clock` are derived from the actual bit primitives and actual list-read subreports. All per-step widths used by the loop proof are obtained from run_refines, which itself derives arithmetic Fits from original integer inputs. The ledger is a fixed polynomial in m,n,bits,count because W is the explicit polynomial from the preceding temporary module. No unsupported numerical global polynomial exponent is asserted.

## Precise clock boundary

The report combines the proved RationalBits Boolean-operation/reduction/copy clocks with finite list-cell, allocation and metadata-control allowances. It is NOT yet a theorem about literal address/tape steps or the Lean compiler's machine runtime. In particular finite IDs/index comparisons, list/word object representation and a complete address simulation must still be joined to a fixed representation model. Full original integer-word encoding/acquisition, the template's acquisition, and the initial row-ID enumeration are separate inputs/preprocessing, not silently generated by this theorem. The work of initializing them must be charged by the caller.

The root's newly acquired dense integer constraints are not yet fed into RawDesign/build/current N-only counter by this module. Connecting that source to physical input encodings, then using the returned selected original IDs in the design/counter, remains a separate execution join. This source does NOT claim a complete all-input factorer bit clock, a changed native long-query rate, or polynomial-space preservation.

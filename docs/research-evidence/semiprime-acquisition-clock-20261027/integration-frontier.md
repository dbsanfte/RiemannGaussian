# Next closed integration target

The prior paper-level N^o(1) bit-time argument and the formal resource-rate
result remain unchanged. This packet makes three missing implementation parts
concrete, but does not assert that assembling their names proves a whole-run
clock. The next program should be a NEW counter, with this literal call path:

    paid indexed enumerations (once)
      -> actual original coefficient acquisition
      -> actual original integer-constraint acquisition
      -> cached labels/group columns and physical integer encodings
      -> actual binary row selector (once per node/head)
      -> cached selected original integer design
      -> existing actual fibre/support/Hermite count
      -> report-preserving public prefix/controller/fallback

Each arrow must carry both the semantic refinement and its actual work.

## Design builder seam

The new constraint family stores the untruncated owner-pullback integer rows.
Read only cached original head columns, or explicitly apply the head mask.
Preserve the old row ordering and tail-first selector input order so the
selected original IDs remain exactly the old selected design. The physical
selector's initial input-word contract must be discharged by an executed
integer encoder, not by noncomputable RationalWord construction or a promised
Fits relation. The input bound is the existing measurementBound; a derived
polynomial bit capacity supplies selectorWidth. Build the physical template
and charge it. Acquire head/assigned labels and finite grouping/column maps
with stored lists/arrays and retained work. No recursive old searchPacking or
row selection may be hidden in an allegedly constant C/grouping field.

The source coefficient and constraint constructors currently each acquire
words/packing. Paying both is valid and remains fixed-polynomial; sharing is
an optimization only after a shared data-producing program is implemented.
Avoid expanding scope merely to force this optimization.

## Counter and public seams

The newest N-only endpoint is PaidScheduledController.run. Its concrete
counter is still CachedSourceCounter. It faithfully retains every report that
that counter returns, but the latter's old raw/build and indexed setup remain
outside it. Substitute the NEW complete setup program only after its exact
runtime design and source-read theorems are established. Then derive the
uniform B in PaidPublicController.factor_work from the actual source/layout
bounds and paid terminal callback theorem. An hb premise is a resource
contract, not the final theorem.

The callback checker budget is already explicit for every reachable prefix.
Public Macro edge/vertex-list construction is distinct from source indexed
enumerations and still needs its report. Include original N decoding, macro
parameters/schedule/guard and finite fallback setup, rather than inferring
constant cost from three outer branch events.

## Physical-cost seam

The row selector now executes RationalBits primitives and finite cached list
reads. Its clock sums primitive bit-arithmetic and metadata-cell/control work;
it is not an already compiled bit-address/tape clock. The remaining source,
fibre/group/support/Hermite and controller ledgers still need integer/rational
primitive implementations and their already-derived intermediate heights,
plus finite-memory address/allocation/control simulation. Polynomial physical
simulation may use the permitted subexponential memory; polynomial space is
not a requirement. A full-tape polynomial overhead is acceptable under the
resource-rate theorem if it is actually established for the whole program.

Only after a single original-input program has a closed fixed-polynomial
bound in the actual scheduled resource envelope may MaterializedRate deliver
the formal N^epsilon (in particular N^(1/6)) theorem. The old native long-query
soft-K^1.25 rate is not changed by this factor-count detour.

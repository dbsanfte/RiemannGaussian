## Supply, unit guards and data-size ledger

The frozen dependency is loaded from the explicitly supplied repository root and fixed reviewed relative path; no hidden factors or field are production inputs. Individual screens run on every distinct prime dividing public m and the supplied prime ell before constructing PackedGauss. For a composite semiprime a nonunit prime screen is proper, even when the combined product gcd would be N. Input N equal to a screened prime is rejected explicitly. The public contract assumes ell prime; the frozen constructor validates this if execution reaches it. A premature proper gcd with an invalid composite ell would still be a genuine proper factor, but the stated primewise interpretation is confined to valid input ell.

Public m factoring, ell primality checking, ell−1 factoring and primitive-root candidate testing are paid within soft ell: even ell candidates times polylogarithmic work remains soft ell. The table is acquired by walking the public auxiliary primitive root, not hidden-prime discrete logarithms. One C_m takes O(log m) explicit ell-term histograms and length-m packed convolutions. Constantly many packed powers have polynomial-size exponent lengths; A=O(m²),S=O(m),h=O(m),A+Nh=O(Nm+m²). The O(m) pair scalars have O(log N+logm)-bit exponents. In the intended ell,m<=N^O(1) regime every exponent remains O(logN) bits.

Nine length-m output arrays and O(m) descriptors are genuinely stored. There is no k-by-k pair-vector output. The byte-Kronecker multiplication inherits the already reviewed carry bound from the frozen implementation, using GMP when available. The theoretical soft O(ell+m) bit ledger is coherent with fast integer arithmetic; it is not a formal theorem about Python runtime. The wrapper does not itself perform the ell-first sieve; its supplied auxiliary parameters may be generated by composite_colours.preprocess or the proved supply algorithm. This API separation is explicitly documented.

# Independent source-preprocessing audit

Reviewed 27 October 2026. Final source checkpoint: `source-preprocessing-hashes.json`, refreshed after all authors confirmed freeze, including the parent's proof-argument-only BlockArray change. This is a paper-level resource audit of the literal executable definitions, not a Lean primitive-machine runtime theorem. The concrete raw-design wrapper being completed by root must still be checked against this interface.

**Verdict:** the inspected source/designer path admits a conservative polynomial preprocessing bound in the *numerical* parameters n, F, M, D=r^(2Q), Q, R, A, with A≤Q and Q≥1 (or explicitly include r for the empty-word case), for the concrete finite dictionaries and maps. There is no enumeration of 2^n assignments on this path. Several important computations are lazy closures rather than globally materialized values; treating them as cached once would give an incorrect finer ledger. Charging their actual repeated evaluation still gives a polynomial. The rational-operation reports returned by the array interpreter are not by themselves this whole bound.

## Input/resource contract

Here n is original Boolean coordinates, F is factors, M is total incidences, and the universal alphabet is **one-slot** `UniversalType r Q 1`, cardinality D. Assume r≥2; allow degenerate small instances to use their explicit fallback. The original owner/factor maps and finite dictionaries are the actual finite network lists/Fin encodings, with polynomial-time lookup, equality and traversal. Arbitrary user callbacks or arbitrary executable Fintype dictionaries do not receive a resource guarantee merely from their types. Let Hε be the binary height of the supplied rational tolerance, and include binary heights/costs of any additional supplied raw integers. These cannot be omitted for an unrestricted RawDesign API.

For a convenient envelope set S=2+n+F+M+r+D+Q+R+A+Hε plus the concrete input-description length. Primitive finite operations may be implemented by flat lists, binary integers and linear lookups. No random-access or constant-time equivalence inverse is needed. The estimates below give S^O(1) bit work and storage on the inspected source-generated path. The fixed exponent has not been tallied gate by gate, and no numerical exponent or tracked exact Lean clock is asserted. In particular polynomial in D is exponential in Q log r, which is precisely the paid source-alphabet parameter; it is not an extra exponential in original n.

## Exact source of potentially large loops

1. `SemiprimeFiniteEnumerations.words/pi/universal` construct r^Q words and D universal symbols by finite recursion. Word length is O(Q); equality and all explicitly chosen finite inverses can be charged O(DQ) or a larger polynomial for linear scans. The incidence list has M entries, the index list n+F entries, and the actual local score-term list has T=M²+Qn² entries.

2. `PackingAlgorithm.computedWords` calls `localAssign` with `sequentialEvaluator`, not the exhaustive `conditionalMean` implementation. Each score term depends on at most four word variables. The proved call bound in `searchWordsCounted_calls` is at most 2(n+F) W T W^4, W=r^Q=√D. Computing a score and its addresses costs polynomial in Q,n+F and the finite input size. Thus a single search costs polynomial; including its local control/arithmetic operations and explicit support/index scans. The finite completion enumerations here have at most W^4 choices, not W^(n+F).

3. `UniversalNumeratorExecution.entry` enumerates active subsets of at most Q positions and expands a j-fold difference into 2^j leaves. The total leaf bound is Σ(j=0..min(R−1,Q)) binom(Q,j)2^j ≤3^Q≤r^(2Q)=D. There is also the displayed R-loop, including zero terms, plus sorting/equality/swap work polynomial in Q. A conservative entry cost is polynomial in D,Q,R,A. This is a genuine finite computation of integer entries, not an entry oracle. The Δ=1 specialization is essential for the stated D parameter.

4. `BinomialExecution.parity` computes the finite integer triangular solve. The preferred tracked `acquireParity` uses A(R+1)+A+R+R² integer arithmetic operations. The currently used core wrapper additionally computes its target powers by ordinary finite power routines; this remains polynomial in A,R (charge even linear exponentiation). The proven coefficient-height bound is R(A+clog2(R+1)+1) bits up to sign/zero conventions. A parity closure is bound once per universalRow call, not once for the entire acquired source family. Each separate constraint call may bind/recompute it again.

5. `mismatchRowCode` tests membership in `correctionColumns`, which can materialize/filter **all D universal symbols**. This is polynomial and must be paid; the syntax constructor is not constant time. Its correction has Q terms, each with a Q-factor basis. Its expression-tree size is at most 6Q²+8Q+3 by the new `SourceExpressionBound.mismatch_nodes` theorem; prescription constants can each invoke the preceding numerator computation. `SourceCodeArrays.compile` recursively caches each child result. Its proved scalar arithmetic/read counts are quadratic in R+1 per syntax node; `universal_array_work` and `source_array_work` substitute the actual node bound rather than an advised expression size. Arrays/finite construction, constants, rational inverses and syntax allocation are additional paid work. The source polynomial itself is never an executable input.

## Packing, pullbacks, and repetition

`computedPacking` stores `label := incidenceType ... (computedWords ...)`. This is a function closure. A `let pack := ...` binds the packing record but does **not** establish that the complete word search was evaluated once and stored as a label array. Calling label can run the word search again. `bucket`, `blockCount`, `lookup`, and `vertexAt` rescan finite lists and may invoke these labels repeatedly. A bucket scans M incidences; the minimum scans D buckets; lookup also scans its bucket and the minimum. All recursion depth is bounded by explicit finite lists. There is no cyclic dependency from the label search back into packing. Multiplying these fixed nesting counts by the single-search bound is still polynomial with a fixed polynomial overhead per requested cell.

`BlockArrayExecution.sourceRow` pulls an incidence row to an original variable by an explicit M-term sum. `SourceArrayAcquisition.acquire` materializes M×n arrays of width R+1. Within those cells it can repeat universal source acquisition and lazy packing operations. Its `read` accessor subsequently accesses retained arrays; it does not regenerate polynomial coefficients, although locating the incidence in an explicit enumeration can cost a linear scan. Thus count M n M potential assembled callbacks rather than one universal polynomial per source row. This deliberately overcounts zeros and does not rely on sharing between different cells.

For the integer matrix, complete blocks B satisfy BD≤M, since their disjoint images are incidences. Consequently the padded index length BD+M≤2M. Even without using that improvement the directly visible bound B≤M gives MD+M, still polynomial. `PaddedBlockExecution.sourceRow` has an M-term outer owner pullback; each complete-block row has a D-term inner universal pullback. It can therefore invoke the universal constraint M D times for a requested global-coordinate entry. The displayed loops do not enumerate subsets of original incidences or Boolean assignments. Wrong-head and zero-padded rows may save work, but the polynomial bound does not use those savings.

## Actual selected design

`RuntimeDesignAcquisition.columns` constructs a filtered original-column list and its explicit finite equivalence. `selection` uses the executed rational row selector on integer rows, not a chosen row basis. For p candidate rows and at most n columns its cached elimination ledger is O(p(n+1)²) rational arithmetic operations, plus polynomial finite lookup. Here p≤2M for the source padding. The selected cardinality is at most n.

`uncache.C` calls a selected-index lookup. Its selected-list computation can be evaluated again for separate entries; `cache` does **not** prove one elimination per group. `cache` does materialize the final selected C values, with at most r n² cells; group/head/size callbacks may also repeat label computations. Charge a fresh elimination and its raw-source callbacks for each such cell, and fresh polynomial scans wherever the lazy size fields are demanded. The dependence graph is acyclic: source→packing/entries→raw matrix→selection→selected-entry cache. This remains a fixed-depth polynomial composition. The fixed-depth composition gives polynomial arithmetic/control work, including all Q sample nodes and all r groups, even retaining histories and doing linear lookup. No numerical aggregate exponent is claimed.

Proof-only `certify` and the SourceRuntimeDesignBridge do not introduce an executable polynomial object or a supplied row-basis oracle. Their locality/rank hypotheses must be discharged by the concrete source-row matches; the generic RawDesign constructor alone does not establish source correctness or source height bounds.

## Rational heights and bit/storage accounting

The search objective consists of sums of local 0/1 tests times the fixed rational constants x²,y² and their offset. Local averages divide by W^s with s≤4. One common denominator, built from the original tolerance denominator, powers of D,r and the fixed local-average denominator, bounds all search comparisons polynomially; it is not the product over an exponential family of unrelated rational callbacks. Fixed assignments only change which 0/1 terms occur. This is why a polynomial number of rational operations has polynomial operand heights here.

Integer numerator differences are sums of at most 2^j signed delta values. Combining the finite subset sum with the proved parity bound gives polynomial bit height O(R(A+log(R+1)+1)+Q+log(R+1)). Integer pullbacks add at most M D such values, adding O(log(MD+1)) bits. No division occurs in those integer rows.

Interpolation nodes are 1..Q. Node denominators and nonzero difference denominators have absolute value ≤Q. A deliberately excessive common denominator for all interpolation bases is (Q!)^(Q+2); include 2^(R−1) for the prescription. Basis products and coefficient sums have polynomial bit height in Q,R and the numerator bound. Truncating arrays introduces no new inverses. For intermediate interpreter arrays, do not use final coefficient bounds alone: for each finite syntax subtree take the PRODUCT of the denominators of every constant occurrence in that subtree. Each subtree coefficient denominator divides that product; multiplication concatenates occurrence lists, addition uses their product as a common denominator. With O(Q²+1) actual syntax nodes and polynomial-height constants this common denominator has polynomial bit length. Numerator heights obey a bound linear in subtree occurrence count times the constant-height bound, plus polynomial degree/combinatorial convolution terms. This covers partial convolutions and sums before cancellation, not merely the final polynomial. Repeatedly constructing the same coefficients does not enlarge these bounds.

Rational elimination is the special structured operation that requires more than “polynomially many arithmetic gates”. Its retained RREF entries are ratios of minors of the **original integer matrix**: an intermediate rank-k basis uses a nonsingular k×k original pivot submatrix, and Cramer's rule bounds all entries by k(log W+log k)+O(k) bits when original row entries are bounded by W. This is the existing `row-height-cost.md` argument from the previous frontend slice. Partial dot sums and scratch products can use a conservative product of polynomially many stored denominators; their bit lengths are still polynomial. Thus no generic repeated-squaring height argument is being assumed. Ordinary integer add/multiply/divide/gcd and rational normalization can be performed in polynomial bit time at these heights.

Storing all explicit dictionaries, words, source arrays, cached selected tables, syntax trees and even the conservative retained elimination histories is polynomial. Linear scans remove any assumption of free array/Fin addressing. The polynomial conclusion includes those lookups, memory copies, rational normalization and temporary heights. It does not include the subsequent exponential counter enumeration, arbitrary external callback generation, or a theorem compiling the Lean definitions to a particular Turing machine.

## Disposition and remaining join

PASS for a conservative constructive polynomial source/design frontend, subject to the concrete supplier instantiating the finite dictionaries, tolerance and maps as described. Existing per-array work reports undercount this whole frontend if read alone; they explicitly state that qualification. Actual source acquisition caches the final M n (R+1) coefficients; actual design acquisition caches selected measurement entries. Word labels, repeated row selection, individual universal entries and padding lookup are not proved globally cached. These repetitions affect polynomial factors and must remain in any sharper asymptotic derivation. No extra 2^n preprocessing was found.

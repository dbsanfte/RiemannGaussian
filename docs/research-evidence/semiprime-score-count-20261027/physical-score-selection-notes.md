# Cancellation, original label selection and uniform source resources

## Arithmetic cancellation is exact

`SourceScoreCancellation.clear_denominators` proves the exact positive-affine relation between the normalized count score and W=n²lambda²U²I+4M²H. `weight_le_iff` proves comparison equivalence, including ties. Only r,lambda,U positivity is needed; M,n and either count may be zero. `bank_square` gives U²=L⁴ for the actual r,Q alphabets, and `scheduled_x` identifies the original caller's scale expression.

The actual source count lanes, rather than hypothetical I/H arguments, are joined by `SourceScoreCountOrder.integer_le_iff`. It uses `CountsObjective.sequential_counts`, which computes the original finite expectation at every prefix. `caller_cardinality` discharges the L⁴=U² identity from the actual source enumeration constructors. No count-answer or final-score-height premise remains.

The original count caps give W<=T*U²*(n²lambda²U²+4M²). `weight_resource_bound` derives S⁹+4S⁵ from actual original dimension caps. Exponential magnitudes are not renamed as small resources.

## Actual source control consumes physical words

`SourceChoiceOrder` permits order-equivalent physical values in the already executed Boolean-ID controller. It preserves the exact original deterministic choice and assignment under cancellation; its decoder remains specification-only.

`SourceScoreChoice` gives the concrete control used by the current original source-label caller. It stores original finite label references and natural loop metadata, calls actual score-word producers twice per comparison just as the original source does, and branches only on `SourceComparisonBits.compare`'s Boolean output. It never decodes a rational score to decide. Each selected prefix is extended along only its actual branch. Its work theorem retains all candidate callback reports, the comparison and finite native control/list stages. It does not claim that the original label references have already been compiled into the physical ID bank; that adaptation is a remaining whole-bit join.

`SourceScorePhysicalSearch.run` acquires original integer weights once and invokes `ScoreCountBits.score` at every actual candidate prefix. That callback has a concrete physical terminal and physical count/padding/accumulation/weight pipeline. Native quantum count values appear only in its specification, never on the physical runtime path. `run_refines` proves EXACT equality with the original `MaterializedScoreSearch.search` for any common offset. No offset or rational scale is an input to the new runtime.

`computedList` executes the original `compileAll` descriptor producer before searching, so it does not accept an advised score program. `SourceScorePhysicalCaller.computed` supplies actual source enumeration fields and dimensions, discharges the cardinality identity and derives the original scheduled x. `producer` caches the actually produced labels and returns the existing paid `labelAt` constructor. `producer_refines` gives every original incidence label exactly. This is a real original producer endpoint; it does not assert that the existing N-only counter already calls it.

## Original resources close the callback and search reports

`SourceScorePhysicalBudget.run_work` obtains score width and clock from the actual count/predicate budgets and actual acquired weight widths. The descriptor ID cap is legitimate original metadata. `computed_work` derives it internally via `SourceSearchState.compileAll_support_lt` for the complete original enumeration. No terminal-cost, score-cost, Fits, numerical-count or output-size oracle is assumed.

`SourceScorePhysicalResources.caller_work` bounds the complete computed-label report by a single envelope of original M,n,r,Q,lambda,U,L,T,N caps. Its monomial witnesses are fixed and input-independent. These resources include the actual finite alphabets/banks and lists; this does not assert a polynomial in their much shorter binary descriptions. The existing public resource-rate machinery can be applied only after all actual public construction and machine costs have been composed.

The reports mix explicit physical bit gates/scans/copies with named native source metadata/control stages. Original `cacheWord` acquisition during extension, native descriptor/index operations, list/reference representation, report-Nat arithmetic and all primitive scratch/allocator bindings still need the complete machine encoding or erasure argument. The new source-label correctness and uniform mixed report bounds are not a full primitive-bit proof.

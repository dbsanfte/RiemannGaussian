# Executed Hermite scalar evaluation and affine products

FINAL FROZEN. Two new modules only: `SemiprimeHermiteEvaluationBits` and `SemiprimeHermiteEvaluationBitsBounds`.

The runtime `evalPrefix template a x len` caches its old word/power once, performs the actual coefficient-times-power, scalar add, and power-times-x Boolean rational instructions, and retains all three reports. Its order is exactly the frozen ascending-power scalar evalPrefix. Actual coefficient lookup is charged using `JetBits.accessCost`; cached-word reads/copies and loop control add 8W+12 each step. `affineValue template x cs` computes one suffix once, then actual c*x, 1+c*x and suffix*factor in exactly the scalar suffix order, retaining all instruction and cell/control work.

No rational coefficient answer is generated from interpretation in these runtimes. Original arrays, slope lists and integer-argument physical words are supplied inputs and their acquisition reports belong to the caller. The proof interprets those inputs only.

`evalPrefix_correct` proves exact scalar value, exact cached integer power and both Valid outputs. `evalPrefix_representation` derives the original common-d representation with numerator len*B*(T+1)^J. Its caps d and (J+1)*(B+1)*(T+1)^(J+1) come only from original coefficients and integer bound, not per-operation Fits advice. `affineValue_correct` proves exact frozen scalar product, Valid and Representation denominator d^length/numerator (d+B*T+1)^length. Every multiplication/addition Fit is proved from that suffix invariant and the original length bound.

`evaluationWidth b J = 8*(b+J+2)*(J+1)` is a public polynomial width. `numeric_bounds` derives all four original-data caps solely from d,B,T<=2^b. The `_at_width` theorems permit this or any larger physical template. Here J in the affine API is the maximum FACTOR-LIST length; it need not equal Hermite jet precision. This intentionally conservative width suffices without arithmetic-width advice. All output reduced numerator/denominator fits are proof consequences, never runtime inputs.

`evalPrefix_width` and `affineValue_width` give unconditional structural width bounds (for positive template length). Actual clocks are bounded by 4+len*(60000*(W+1)^3+accessCost+8W+12) for evaluation and 4+length*(60000*(W+1)^3+8W+12) for affine values. These use `RationalBits.executeOperation_cost` for the real three instructions per frame, including reduction/fit; original input physical Width is the legitimate clock premise, not intermediate semantic advice. Acquisition of those inputs, literal memory addressing/tape compilation and the final whole public clock remain separate.

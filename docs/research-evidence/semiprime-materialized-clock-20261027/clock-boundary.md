# Boundary of the present whole-program claim

The preceding paid-materialization packet contains an independently reviewed
paper-level ordinary bit-time proof for a concrete original-input algorithm:
fixed polynomial overhead in

    S = poly(n) + Cq + Y + 2^h + 2^w,

with log S=o(n), n=Theta(bitlength N), hence N^o(1) and in particular an
asymptotic N^(1/6) bound. Subexponential storage is permitted. The enormous
crossover precludes a practical speedup claim.

This packet strengthens the Lean connection to that algorithm. Its
MaterializedRate theorem proves that every fixed polynomial in the actual
support/summary/head/scope resource envelope is below every positive power
of N eventually. That theorem is a numerical resource bound, not a premise-free
bound on the N-only implementation's running time.

The remaining formal dependency chain must be completed in this order:

1. One original-input controller must call the paid word, packing, universal
   row, constraint/design, fibre and Hermite suppliers. A new supplier's proved
   value equality does not by itself attach its work to a caller that still
   literally invokes the previous supplier. The new source already acquires
   score descriptors, offsets, searched labels and source-array payloads.
   Initial public graph, schedule/tolerance, finite alphabets and enumerations
   still require their complete acquisition charges. Cached coefficient and
   packing data must be shared
   explicitly through runtime data, not through repeated lazy function calls.
2. Each actual scalar operation and temporary value must be replaced by the
   proved finite binary arithmetic under derived width bounds. The new exact
   selector minor theorem and temporary-expression bounds cover real prefixes;
   no arbitrary oracle certifying intermediate sizes may be inserted. Whole
   selector word arrays and the whole counter's physical arithmetic still
   need a joined run, including all additions, products, division, comparison
   and rational reduction in the executed trace.
3. The finite-list/array/control and physical addressing/storage simulation,
   initialization and output decoding must be composed with these operations
   into one closed bit-cost bound. The current public prefix wrapper projects
   each count value and records query count; it does not yet accumulate every
   query work report into the public return value. That aggregate controller
   clock must also be supplied. Only then can MaterializedRate and the
   eventual guard theorem absorb the finite fallback and discharge the complete
   all-input factoring clock theorem.

Selected work fields in the new Lean modules are deliberately labelled
scalar/register/list/array ledgers. They are not silently equated to primitive
bits or Turing-machine steps. The older native long-query bound remains
soft K^1.25; the factor-count detour is the route producing the paper improvement.
The formal head tables are cached once per node. Original local truth callbacks
are still re-evaluated within the support/summary/head traversal, and that work
is explicitly charged; the Lean path is not claimed to have the identical
once-per-query truth-cache trace of the prior Python algorithm. No additional
representation search, empirical scaling fit, or finite successful example
closes these proof obligations.

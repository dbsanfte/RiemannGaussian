# Next whole-bit integration after the acquired-ID source search

The current acquired word bank, Boolean-ID environment, original terminal predicates, physical local counts and valid-menu source search are closed at their stated physical/typed-metadata interface. Their decoded Word functions occur in proofs, not the new runtime data path. The next task should consume the actual selected ID list, rather than build another score-callback interface. The public N-only primitive-bit goal remains open.

1. Read actual incidence labels from selected IDs. Use Environment.initial and physical reverse-prefix readFixed with acquired owner/factor key words to return the two candidate IDs. Prove this pair decodes to the original incidence label. Charge the original owner/factor/index descriptor acquisition; do not construct runtime Word functions from decoded IDs.

2. Execute original source packing over these physical pairs. Enumerate the exact head-major pair menu from bank.ids, test its two IDs physically, and execute bucket, position, minimum/block-name and address scans. Valid-menu injectivity already licenses ID equality. Preserve old tie/order and multiplicities. SourcePackingState and the existing allocation/work bounds are reusable proof resources, not yet this concrete physical packing program.

3. Connect physical pair labels to universal prescription/coefficient acquisition. SourceInterpolationGeneratedBits already executes the compiled arithmetic VM without encoded-bank or Fits advice; its source frontend still receives original functional universal labels. A new frontend must read acquired coordinate rows/IDs to generate the original integer prescriptions and parity literals. Reuse SourceUniversalHeight, BinomialExecution/Bounds/Tracked and SourceInterpolationBits all-subtree bounds. Do not introduce a supplied leaf-bank oracle or decode physical labels into a functional runtime cache. Native parity/choose/subset/prescription construction still needs execution lowering. When bounding subset work use the actual fast r>=2 guard: 3^Q<=r^(2Q), with honest finite fallback.

4. Keep the existing SourceArrayProgramIR/Lowering/GeneratedBits backend. A concrete literal-ID frontend can reference actually acquired physical leaves, preserving proved Safe and original interpolation semantics. This is a proposed connector, not an already established physical source compiler.

5. Execute universal cache lookup and source pullback on physical coefficient arrays. Reuse original cache key counts, SourcePullbackHeight/AcquiredArrayState/Bits suffix bounds and physical JetBits/WordFold operations; retain actual reads, copies, suffix additions and all callbacks. Return one acquired physical source-row cache with a coefficient-refinement theorem to the original source acquisition. Avoid a decode-to-host-rational/re-encode detour.

6. Bind that cache and physical label/packing output into actual raw constraints/design and the public counter. Existing encoded physical row selection, PaidRuntimeDesign and full setup semantics help, but need an exact new data path from acquired rows rather than a supplied matrix or old functional source call. Only then switch a NEW N-only scheduled endpoint, retain every prefix-count report, decoder and finite fallback. Isolated source-label equality does not switch the existing public runtime.

7. Finish native finite metadata, incidence/owner/index acquisition, descriptor generation, parity/prescription/syntax construction and the full auxiliary-state/address/clock-erasure model. Existing traces describe selected executions/state views and do not automatically prove all allocation/tape costs. A conservative flat sequential lookup overhead polynomial in the existing materialized resource sum is acceptable; polynomial space is not a requirement. Preserve actual local/head exponential resources, never substitute a global 2^n bound.

Once an actual aggregate primitive clock is bounded by a fixed polynomial in those already scheduled resources, existing PublicResourceRate/MaterializedRate and Hermite report resource theorems provide the asymptotic rate step. The current mixed physical/native reports must not be renamed primitive bit steps before that join.

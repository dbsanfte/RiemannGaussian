# Next primitive-clock slice: keep the actual algorithm, replace its remaining scalar execution

Read-only plan after the thirteen-module report-rate slice. The proved result is a subpower bound for the **actual retained mixed report** of the N-only controller. It is not yet a bound for all primitive bit or tape steps. No polynomial-space target is needed: materializing all currently bounded finite tables is acceptable if its total time/bit-size is a fixed polynomial of the proved resource envelope.

## 1. Exact live path and the remaining distinction

The live path is `FullSetupScheduledController.run` → `FullSetupPublicController.factor/search/prefixRun/counter` → `FullSetupCounter.count`. Its count executes paid indexed enumeration, `MaterializedOriginalSource.acquire`, `PaidRawAcquisition.acquire`, `PaidRuntimeDesign.build` (including `EncodedRowSelection.select` and physical `RowSelectionBits.run`), then `MaterializedFibreNative.count` and acquired Hermite reconstruction. Every prefix reacquires that setup; the new report and rate proofs correctly retain these repetitions.

The live source and native count still have `ℚ`/`ℤ` arrays and scalar operations, not word arrays, in several computational definitions. For example `MaterializedOriginalSource.acquire` computes rational score scales and attaches rational coefficient arrays; `NativeGroupExecution.localRun` calls `LocalArrayFrontend.nativeLocal`, not `LocalBits.localEvaluateBits`; `AcquiredHermite.node` calls the rational `HermiteArrayHeight.hermiteNode`. Showing their returned values fit does not execute their arithmetic with bits. Conversely, the physical selector really is called by the live full-setup path; that part must not be described as merely an unconnected minor/height lemma.

There is no file named `SemiprimeNativeLocalBits.lean` in this snapshot. The reusable physical local core is `SemiprimeLocalBits`, with correctness and bounds in `LocalBitsCorrectness` and `LocalBitsBounds`.

## 2. Already proved execution and bounds that should be reused

### Rational words, jets, and actual table entries

* `RationalBits.executeOperation`, `executeOperation_correct`, `executeOperation_cost` implement add/multiply/negate/inverse through physical words, reduction and fitting. `fits_of_representation` derives Fits from a common representation; it is not an output-height oracle. `reduceBits_cost_width` and `fitRationalBits_cost` cover canonicalization/copying.
* `DotBits.dotBits_correct`/`dotBits_cost` implement cached rational dot products. Its hypotheses include the actual suffix representations needed to keep intermediate widths valid.
* `JetBits.addBits`, `scaleBits`, `multiplyBits` are actual physical array loops. Their `_correct`, `_bounded`, and `_cost` theorems account for per-coefficient work; `accessCost`, `collect_cost` and the supplied template remain explicit.
* `PolynomialCodeBits.compile_initialized` computes a sufficient template from the actual expression/word constants and proves exact rational-array refinement, using `requiredWidth`. `compile_cost`, `compile_refines`, `budget`, `safe_of_requiredWidth` are the relevant contracts. Computing `requiredWidth`, building the expression and physically acquiring its constants are explicitly separate from `compile.clock`.
* `LocalBitsCorrectness.local_correct` and `LocalBitsBounds.local_correct_at_public_width`/`local_clock` provide physical Boolean multilinear evaluation, including both recursive branches, all actual table callbacks, and jet arithmetic. The clock is `2^w` times a fixed polynomial, not a unit local oracle. Existing public entry modules `MacroEntryBitCheck` and `SubdividedEntry` (in particular `publicSubdividedEntry_correct` and `publicSubdividedEntry_polynomial`) cover the actual original/equality vertex predicates; do not redo only the original vertices and omit subdivision equality.

### Physical selector and measurements

* `EncodedRowSelection.select_correct` and `select_work` really acquire/copy integer cells, construct IDs/template and call `RowSelectionBits.run` once. The returned original-integer cache prevents expensive rereads by `PaidRuntimeDesign`.
* `MaterializedSelectionHeight.state_binary_bounds`, `MaterializedSelectionTemporaries.residual_trace_fits`, `normalize_trace_fits`, `update_trace_fits` already derive all selector intermediate widths from original integer bounds. `RowSelectionBits.run_decoded_eq`/`run_clock` are actual executed refinements; no new minor advice is needed.
* Remaining encoder scope: `EncodedRowSelection.digits/encode` uses scalar `Int.natAbs`, quotient and remainder to construct bits. Its digit/control ledger is not yet a primitive implementation of those scalar operations.
* `MeasurementBits.dot_value/dot_cost`, `test_correct/test_cost`, `indexedTest_correct/indexedTest_cost`, `representative_found/representative_work` already give physical signed measurement and representative search. They are not automatically the functions used by the native cached-head tests: an explicit word-cache/test adapter is still needed.

### Height theorems needed for the joins, not just final outputs

* Actual source coefficients: `SourceRowHeight.builtLayout_row_representation`, `rowDenominator_pos`, `rowDenominator_le_power`, `rowCoefficientBound_le_power`, `rowNumeratorBound_le_power`. These apply to the actual indexed built layout, not a desired default-layout identity.
* Shift and local **temporaries**: `LocalExecutionHeight.shiftFrom_bound`, `shiftFrom_product_prefix`, `acquireCorrectedFin_bound`, `localEvaluate_trace`, `nativeLocal_trace`; `LocalExecutionBitBounds.shiftFrom_prefix_fits`, `localStep_prefix_fits`, `localStep_buffers_fits`, `localStep_terms_fits`, `nativeLocal_fits`. These are stronger than an endpoint bound, and can discharge word operations at every executed Horner/convolution/local branch.
* Group/fibre/support partial sums: `FibreAccumulatorHeight.built_varying_accumulator_representation`, `built_recordwise_accumulator_representation`; `CounterPacketHeight.built_masked_terms_representation`, `built_nodePacket_representation`, `rawNumeratorExponent`, `rawBound_le_power`, `packetDenominator_le_power`. A coarse bound with a formal `2^(O(n))` count inside a **magnitude bound** is harmless if its binary exponent remains polynomial. It is not permission to run `2^n` assignments.
* Hermite **prefixes**, including inverse-dot temporaries: `HermiteArrayHeight.buildAffine_dotPrefix_representation`, `inverse_dotPrefix_representation`, `quotient_dotPrefix_representation`, `cardinalJet_suffix_representation`, `cardinalZero_suffix_representation`, `hermite_prefix_representation`, `hermite_prefix_dyadic`, `hermite_prefix_bit_lengths`, `hermite_bits_polynomial`. These avoid assuming only the final rational answer is short. The executed native/summary/support arrays still need exact prefix correspondence to these mathematical sums and products.

## 3. Genuinely missing execution joins

1. **Source scalar/word acquisition.** `MaterializedSourceWords` is an actual scalar/list producer, not a supplied packing oracle, and its searches are paid in the mixed report. But its rational score averaging/comparisons and powers are not yet physical rational-word operations. `MaterializedScoreSearch.expectation` explicitly divides by alphabet length, and its evaluator/selection uses exact rational values. Similarly, `MaterializedSourceRows`/`SourceCodeArrays` build and compile rational-valued expressions. The physical `PolynomialCodeBits` compiler is available but not called by that live source producer. Initial constants and every score/AST/interpolation intermediate need common-denominator/height bounds plus executed word construction/comparison. Final coefficient size alone is insufficient.

2. **Native corrected-port and reduction chain.** The live `nativeLocal` includes rational shift/Horner/corrected-column acquisition before multilinear evaluation. `LocalBits` currently supplies the local evaluation core; it does not silently pay this preceding rational-to-word stage. The existing shift-prefix bounds make a physical shift/corrected-port adapter a concrete small next connector. Then actual group products, fibre/summary accumulators, support weighting and the Hermite node/sum must call physical add/multiply/inverse/dot loops. There must be a single retained clock from those calls, not a new independent number assigned after equality of final values.

3. **Actual native prefix alignment.** The available common-representation bounds must be joined to the precise `productList`, cached summary scans, support traversal and Hermite arrays. For a homogeneous numerator/common denominator, retain that shared denominator through sums rather than invoking a generic rational-circuit height recurrence that could double at every step. The source syntax-tree budget similarly bounds every subtree, not just the root; a tree-size/common-denominator argument is appropriate, while an arbitrary DAG/recurrence cannot inherit it without proof.

4. **Finite representation/control.** Runtime groups, `Fin` indices, function-valued words, grouping equivalences and cached array getters still have abstract finite-value operations. The mixed report includes explicit list/cell/control allowances, but it is not a literal address/tape implementation. Materialize all finite lookup tables, original descriptors and group/column maps once in binary indexed arrays/lists; charge actual copies/scans. Function-valued equality is particularly not free merely because its domain is finite. Existing paid enumerations fix exact tie order; do not replace them with a different search because it has the same count value.

5. **N-only boundaries.** The actual schedule evaluates integer logs, square roots, powers, rationals and the guard; the paid scheduled wrapper adds only selected branch/control work, not a full bit implementation of all these computations. Prefix `Nat.floor`/zero testing, finite fallback remainders, and the integer encoder's digit extraction also need physical implementation or a proved generic simulation. `PaidFactorDecoder` already supplies the actual output reconstruction report. Preserve exact every-occurrence prefix restrictions and false-first consistency when replacing the counter: the current controller proofs can transfer final values once the new executed count refinement is proved.

## 4. Recommended next connected slice

The highest-value narrowly scoped first connector is a **physical corrected-port/local call on the actual source cache**, followed immediately by its use in a physical `nativeGroup` (not another standalone local-height theorem):

1. Acquire/copy source coefficient words with a derived public common width, using the actual source expressions/word compiler rather than supplied requested coefficients. If a temporary boundary accepts a source-word cache, label that as a partial stage and keep source acquisition explicitly outside its claimed clock.
2. Execute Horner shifts, corrected-column sums and mask operations with `JetBits`/`DotBits`, deriving every fit from the existing prefix bounds.
3. Call `LocalBits.localEvaluateBits` with the actual subdivided entry-word checker; call physical jet multiplication for the actual gated group factor list. Prove decoded equality to the current `NativeGroupExecution.nativeGroup` and preserve one real summed clock.
4. Attach that group executor to the existing finite head/summary/support controller. Use the already proved accumulator and Hermite prefix representations to implement those rational folds with the same backend. This should produce an actual bit-backed `count`, not only a theorem that a different function could evaluate its final polynomial.

In parallel, source acquisition can be closed by producing a **single actual word-backed source bundle** (labels, integer constraints and coefficient arrays), used by the same full-setup caller. This reuses `PolynomialCodeBits` but must pay AST/constants/template generation and exact rational score comparisons. Do not leave it as an optional unused producer beside the old rational producer.

A time-only alternative is a generic flat-memory simulator for the existing scalar/list execution. It is viable only if there is an actual instruction/control trace refinement and a uniform bound on **all** executed scalar prefixes and memory lengths. It may materialize all bounded tables, and may pay a fixed polynomial in the current resource envelope and width. It cannot simply read `run.work` as a machine clock, or take arbitrary rational callbacks as already evaluated. Choosing this alternative would reduce duplicated word-level rewrites, but the new trace/compiler and its data-path correctness are substantial proof obligations, not an immediate consequence of the rate theorem.

## 5. Finishing criterion

A sufficient final join is a concrete original-input executor with the same all-N factor output and a proved bit clock bounded by a fixed polynomial of the current public resource envelope and a derived prefix width. Table acquisition, schedule, every setup/count query, physical arithmetic, lookup/copy/control and decoding must occur on that executor's actual path. The existing `FullReportRate.resources_le`, `run_le_rate_budget`, `run_report_subpower` and `run_report_sixth` identify the current resource/report endpoint. Apply the underlying fixed-polynomial `MaterializedRate.public_fixed_polynomial_subpower` closure to the new bit-execution bound; do not infer a fixed-polynomial bit bound merely from `run_report_subpower` alone. Polynomial space, a new knot/torus representation, an order oracle, or a fresh search for generic rate exponents is not required.

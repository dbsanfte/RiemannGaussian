# Exact local branch elimination in the original source query

Let L=r^Q be the actual canonical word-bank cardinality. The original padded local counter enumerated m active variable keys, counted true completions, then multiplied by L^(4-m). This checkpoint replaces that execution with exact arithmetic classifiers for the actual original source family. It does not change the objective, candidate order, normalization or ties.

## Why the incidence count collapses

An original incidence term asks for owner-word equality and factor-word equality. These keys originate in opposite sides of the original vertex/factor sum type. SourceIncidenceNamespaces proves that the complete acquired index scans preserve all four cross inequalities. Therefore the two equality constraints involve disjoint variable sets. This condition covers every actually compiled original descriptor; it is not an added hypothesis about the network, unknown factors or selected word values.

For one pair, a repeated key is tautological. A distinct-key equality with an active endpoint has exact conditional probability 1/L, because the actual word menu is complete and duplicate-free. With both endpoints fixed, the actual original words either agree or conflict. Previous defaults and overrides do not constrain an active key that the original completion replaces.

If either fixed equality conflicts, the padded count is zero. Otherwise let d be the number of nonloop equalities having an active endpoint. There are two disjoint equalities, hence d is 0,1 or 2, and the padded count is exactly L^(4-d). Thus only 0,L^2,L^3,L^4 can occur. SourceIncidencePairAverage and CountFormula prove this for the actual original recursive paddedLocal, every Nodup remaining list and every typed original environment. The proof uses exact finite averaging and positive L, not random samples or an assumed rank/coverage oracle.

## Why the head count collapses

A head term asks whether two words have the same colour at q:Fin Q. A fixed-colour fibre has exactly r^(Q-1) words, proved by restricting to the other coordinates. Two independent words agree there in exactly r^(2Q-1) ordered cases. Transferring these bijections through the actual complete ordered menu and original active scan gives:

| Head case | Exact original padded count |
|---|---:|
| Same variable key | L^4 |
| Distinct keys, at least one active | r^(4Q-1) |
| Both fixed, colours equal | L^4 |
| Both fixed, colours unequal | 0 |

SourceHeadCountFormula.head_padded_original proves this at every original prefix. Q=0 has no head descriptor; r=1, repeated keys, previous overrides, zero-active cases and repeated source terms are covered without changing the objective.

## Executed replacement

SourceCountPowers acquires r with the actual Boolean increment encoder and physically multiplies to produce r^(2Q),r^(3Q),r^(4Q),r^(4Q-1). It never expands their values into unary lists. Keeping the fixed base on the multiplier's left side gives actual width at most 2k*base.length+1 after k products. All four acquired payloads have width at most W=8Q(r+1)+1, with fixed polynomial acquisition work in original r,Q. This is a conservative bound using the actual magnitude-linear input encoder, not a claimed logarithmic encoder.

The physical incidence classifier tests the two original equalities. Loop/free cases need no anchor truth. Fixed cases acquire the variable keys, read actual candidate IDs and compare those IDs physically. Valid-menu injectivity proves these are exactly the original word equalities. The result copies the acquired square, cube or fourth word, or returns literal zero. It performs no row lookup or completion assignment sweep.

The physical head classifier copies the fourth or head-fibre word when a key repeats or is active. Only the distinct fixed/fixed case executes the actual physical bank/coordinate predicate before choosing fourth or zero. All copies, membership scans, key acquisition, environment reads and comparisons remain in reports. Native descriptor equality, membership and report stages remain explicitly native metadata at this boundary.

SourceClassifiedCounts evaluates each original descriptor once with these concrete classifiers, accumulates both lanes using actual Boolean adders, copies the real prefix IDs and computes the weighted score physically. No old count traversal, Word function, decoded prefix, push callback, terminal truth oracle or encoded count answer supplies its data. Both lanes have structural width at most W+T, where T is the actual program count.

SourceClassifiedWeights reuses the acquired square U=r^(2Q) to construct the two actual integer weights. This removes the old unary U initializer and its magnitude-linear re-encoding. SourceClassifiedSearch acquires bank, powers and weights once and drives the unchanged SourceChoiceBits controller with the classified callback. SourceClassifiedCaller acquires original metadata and descriptors itself. Its indexed_original theorem returns the exact old source labels after proof-only decoding, for positive r and lambda. Every original candidate position and left-on-tie decision is retained, including zero scores.

## What the bound does and does not establish

ClassifiedSearchBudget.indexed_work bounds the actual executed caller report. ClassifiedResources.indexed_report_actual and envelope_monomial provide one fixed polynomial in a common cap on nine original resources: n,F,r,Q,lambda,M,L,T,V, where M=sum arity, L=r^Q, T=M^2+Q*n^2 and V=n+F. No separate U resource or unary L^4 padding remains in this displayed bound. Materialized L is still explicit; it is not assumed polynomial in its binary description.

The current runtime still constructs T score descriptors and scans the acquired candidates. Its word-bank lookups, finite metadata and adder padding are paid conservatively. This is not yet a near-linear bit acquisition theorem, a complete primitive-machine clock, or a new N-only public factorizer. Packing, universal coefficient-cache construction, pullback, public composition, native metadata/parity/prescription/AST lowering and full scratch/reference/pointer/tape/report accounting remain to finish the overall sixth-rate goal.

The successor histogram investigation targets the remaining T list itself. Its separate scratch algebra and sparse grouping results are research helpers; the original finite-prefix aggregate/state/dictionary implementation still needs a proof and paid runtime join. Those obligations are not hidden inside this checkpoint's exact local-count theorems.

# Independent acquired-prefix/public factor execution review

Read-only review of the frozen `SemiprimeAcquiredPrefixSearch` and `SemiprimePublicAcquiredExecution`. ScheduledFactorExecution is reviewed in the addendum only after its author freezes it. This is a semantic/operational audit, not a new primitive-runtime theorem. Source hashes are recorded separately.

**PASS for the stated guards.** The prefix callback is an actual base local bit checker followed by a finite every-occurrence scan on the SAME original scope. It does not introduce singleton prefix factors or extra variable occurrences. The public exact port equivalence transports the actual occurrence-two graph, proving indexed_occurrences≤2; indexed_incidence_count also proves the exact total M=2*wireCount. Prefixing therefore preserves B=2 and the original arity budget. The generic prefix theorem requires actual coverage, and the public graph discharges it via indexed_coverage. It does not assume an absent variable is constrained by an empty local scan.

The entry remains literal integer zero/one. The acquired scalar counter is proved equal to the rational prefix indicator contraction. Its natural conversion uses Nat.floor only after proving that scalar is the exact nonnegative integer acceptedCount; no rounding or numerical approximation is involved. All sample/degree/precision guards are explicit. An arbitrary unguarded parameter choice has no correctness guarantee, which is why the scheduled wrapper must test its sufficient guard.

The recovery is genuinely false-first: count the empty prefix, then one false-child prefix per wire, retain the selected bit and recursively extend THAT prefix. The imported select_sound proof preserves a witness of each current prefix and ultimately gives one common original accepted assignment consistent with every returned bit. A failed false child implies the true child is inhabited because the parent was inhabited. This does not combine separate CRT witnesses or independently selected marginal bits. The selected index list is exactly finRange wireCount; selectedBits then reconstructs that same witness. Search uses at most wireCount+1 acquired count calls. It is not a supplied count oracle: every callback invokes the actual acquired source interpreter.

The public interface uses explicit constructor enumerations for vertices/edges and transports each port through their proved finite equivalences. The entry callback is the actual SubdividedEntry.publicSubdividedEntry, including equality vertices. indexed_factor_count joins the exact public tensor/factor-pair bijection. decodeOperand uses literal little-endian binaryDecode on the source input's false half-edge and the original radix weighting. Equality subdivision/accepted graph semantics justify using that half-edge consistently. decodeOperand_eq connects to sourceOperand, and selected_factor_pair proves both decoded operands≥2 and their INTEGER product exactly N. factor_sound hence yields a proper divisor, not just a modular or ring factor. Empty search is equivalent to no ordinary nontrivial ordered pair, including the prime/square cases. factorNat handles N=0 by an explicit branch.

## Resource qualifications

The algorithm recomputes source/design acquisition in each prefixCount invocation. There is no cross-prefix cache in these definitions. Multiplying the full acquisition/count cost by at most wireCount+1 is required; the query-count theorem alone is not a runtime theorem. The original factor callback has its prior explicit polynomial physical bit-checker bound. The extra prefix budget `fixed.length*(3*arity+2)+1` records finite equality/scan logic, but does not by itself prove primitive bit cost for arbitrary Fin-coordinate comparisons, list/finite-equivalence indexing, array acquisition, natural floor, assignment reconstruction, or the binary/radix decoder. These remain in the complete control/address/recovery clock join.

Thus this slice closes the actual original-input count-to-consistent-witness-to-integer-factor semantic route. It does not close the whole guaranteed factoring bit-time bound. No finite example, unproved layout answer, supplied native row or supplied count is used in this review.

## Final scheduled-wrapper addendum (author freeze confirmed)

Read the final `SemiprimeScheduledFactorExecution` after its strict/root15/all-generated gate, and refreshed all three source hashes. **PASS.** All runtime parameters are actual Nat/Rat functions of the public integer's indexed Boolean wire count. The guard has only decidable integer/rational operations; real logarithms occur solely in its comparison proof. There is a separate computed positive-group branch before creating NeZero, so even schedules with zero groups have a legitimate executable fallback rather than an assumed instance.

`precision=2*wireCount*degree/points+1` is not advice. The exact final `indexed_incidence_count` identifies total arity with 2*wireCount; with points>0, Nat.lt_mul_div_succ then establishes precisely M*R<Q*J. The earlier interval endpoint/start transcription is fixed: guard_interval explicitly composes A≤A+R with the proved A+R≤Q, obtaining the start bound needed by the source counter. No stronger conclusion is silently read from the endpoint lemma.

The natural-input algorithm branches at N=0, then on groups>0 and the sufficient fast guard. Every failed guard uses the literal `trialFactor` interval; its soundness and completeness are proved independently. On a successful guard, run_sound/run_none_iff apply the actual public acquired search with the derived precision, interval and positivity guards. Therefore the final definition is functionally sound/complete for ALL natural inputs: a returned integer is a proper divisor, and none means no ordinary nontrivial factor pair. It is not merely a conditional fast-branch correctness result.

The cast helpers are ordinary elementary inequalities on abstract Nat/Rat values, not an alternative arithmetic assumption. log_nat_le_clog uses ln(a)≤clog2(a); the integer width guard is therefore a sufficient bound for the real-log source guard. The converse connection takes the extra executable integer-width and rational-load checks explicitly, rather than incorrectly deducing a ceil-log bound from a smaller real-log one. eventually_fastGuard composes the already-proved public executable guards with actual bitLength→infinity. eventually_run_fast then proves that the literal run actually selects the source-counter branch for all sufficiently large inputs. This is stronger than merely displaying a favorable parameter tuple.

The fallback materializes List.range N and is not itself a polynomial-log-input implementation. Its use is confined to finitely many N by the proved eventual guard; a final resource theorem must still attach its finite-case execution/storage cost and the source/control/bit costs of the fast branch. The final theorem does not provide an explicit universal threshold, a full primitive clock, or an N^o(1)/1/6 bit-time bound. The small N0/1/2/9/15 controls reported by the author all use the fallback; they diagnose totalization/fallback only and are not execution tests of the huge scheduled fast branch. No finite test was used in this review.
